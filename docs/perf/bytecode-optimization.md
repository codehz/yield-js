# 离线字节码优化计划

> 本文是实施计划，不是当前能力或性能报告。现有契约见 [内部契约](../internals.md)，测试分层见 [测试与用例契约](../testing.md)。

发布时单独编译源码，运行环境只消费预编译 `Build`，不在启动路径解析或优化源码。允许更改字节码和 VM，以稳态执行、启动与恢复开销为收益目标；编译时间不计入运行延迟，但仍记录离线构建耗时、峰值内存和产物大小，防止优化失控。目前的优化排序来自源码调查，不代表已测得的热点。

## 1. 先建立基线

基准入口、复现命令与首轮数据见 [性能基线](performance-baseline.md)。

在 [`yield-harness`](../../crates/harness) 中增加独立的 release 基准入口，复用现有宿主和脚本夹具，不增加语义测试 harness 或外部 JS 工具链。固定源码、宿主输入、依赖锁、Rust 工具链、目标平台和运行参数；保存基线提交、构建配置、工作负载版本与原始样本。基线以当前编译流水线和 VM 为准；以后每个 pass 可在同一版本中单独比较开关前后，VM 布局改动则同时保留变更前版本做端到端比较。

| 工作负载 | 主要用途 |
| --- | --- |
| [React 自定义 renderer](../../crates/harness/tests/e2e/react_compat.rs) | 扩展现有夹具，分别量模块初始化、首次提交和固定输入的重复更新；校验宿主提交结果。 |
| 数值循环、分支密集函数 | 量指令数、分派和数值专用化；保留非数值输入用于慢路径验证。 |
| 短调用、闭包读写、静态属性热循环 | 分别量帧分配、捕获绑定定位、属性查找；避免把三类开销混成一个分数。 |
| 密集 `await`、同步/异步生成器、带 `finally` 的挂起流程 | 用测试宿主主动交付完成，不计外部等待；分别量保存、恢复和继续执行，覆盖成功、拒绝以及生成器的 `next`、`throw`、`return`。 |

- **分开计时**：离线编译及产物编码；产物读取/解码；构建校验、宿主链接与 VM 派生元数据；模块实例化/求值及初始化微任务；首次入口调用、稳态执行；快照捕获、编解码、恢复及首次续跑。运行计时使用事先生成的产物，不把编译混入启动。首次运行用新 VM，稳态用预热后的 VM；注明是否包含文件 I/O、缓存状态和采样次数。
- **分开诊断**：计时用无计数器的 release 构建；计数另跑相同输入。记录动态 opcode/分派数、帧分配和槽数、属性/环境查找及慢路径次数、每次挂起保存值数、快照与产物字节数。报告中位数及离散程度，不把微基准收益当作应用收益。
- **验收方法**：先重复跑未改动版本，测出自然波动并固化基线；每项优化记录目标指标、对应的运行时计数和代码体积代价。收益不能稳定超过该负载的自然波动，或代表性负载的启动、恢复、稳态出现未说明的回退时，不默认启用。记录实测结果再更新优先级。

## 2. 第一批优化：少执行指令

已实现下列两项，独立基准与启用依据见[第一批优化对照](bytecode-optimization-round1.md)。

优化前，[`LoweredFunction`](../../crates/compiler/src/ir.rs) 用 VM `Instr` 表示逻辑寄存器代码；复制传播仅限直线路径，活性分析只删无用的纯槽写入。本批优化层位于绑定提升之后、物理槽分配之前，最终布局负责生成指令、跳转目标、异常和恢复表。

1. **显式 CFG + 跨块常量/复制传播。** 从常量分支折叠、不可达块删除和纯写入 DCE 做起。统一重映射跳转、保护区、异常落点、`await`、`yield` 和生成器首次入口。优化完成后重新计算活性与保存集合。暂不引入全量 SSA；只有后续类型分析、值编号或内联确实受可变逻辑寄存器限制时，再迁移到带块参数的 SSA。
2. **静态属性键指令。** 为编译器已知的字符串键选择 `GetMemberConstKey` 一类指令，复用通用属性读取语义，只省键的帧槽与通用键分派，不承诺消除属性查表。与 CFG 优化独立比较。若两项都完成并有独立收益，再试仅对已证明为 Number 的操作选择专用指令，以及融合无其他用途的比较结果与分支。

## 3. 下一批按瓶颈排序

| 实测瓶颈 | 候选改动 | 边界 |
| --- | --- | --- |
| 捕获变量沿父环境重复查找 | 已完成：模块绑定直接寻址模块环境；无每轮环境且闭包创建深度唯一的函数使用固定 `(depth, binding)`。见[直接环境访问对照](binding-direct.md)。 | 共享单元格、模块活绑定、未初始化状态、每轮捕获必须保持；其余路径保留 `GetBinding` / `SetBinding` 回退。 |
| 属性表与原型查找 | 已实现小型属性表（≤8 键）的排序向量、大表 `BTreeMap` 回退，以及 `SetMember` 的写侧单态缓存；按站点、接收者、布局和槽定位，不缓存旧值。读取仍走通用路径。见[属性表与写缓存对照](property-cache.md)。 | Proxy、访问器、原型链和异形索引先走通用路径。缓存由 VM 持有，不进快照，恢复后为空；读缓存因 React 回退未启用。 |
| 调用分派或帧分配 | 已实现函数 ID 的密集查找与稀疏回退、`classify` 结果复用，以及 `Rc<Build>` 构建句柄；帧缓冲复用和小槽内联因短调用/React 回退未启用。见[函数索引对照](function-index.md)、[调用分派对照](call-dispatch.md)、[构建句柄对照](build-handle.md)。 | 保持 `this`、闭包环境、异常和求值顺序；索引和分派信息都是加载后派生元数据，不进入字节码或快照。VM 仍不跨线程共享。 |
| 保存值或帧槽过多 | 把可安全重建的纯常量移到恢复入口，再评估活跃区间拆分和瞬时槽合并。 | 不重放属性读取、转换或调用；保持持久槽不在不同活值间复用。 |
| 指令取用或分派 | 已实现 `Instr::Binary` 的双 Number 快速路径、右侧字面量的 `BinaryConst` 立即数、比较条件与 `&&` / `||` / `!` 的分支融合、单用途 Binary/Unary 条件窥孔、Number 一元/内建快路径，以及数组数字索引与 `.length` 快路径。见[数值快速路径对照](number-fast.md)、[常量右操作数对照](binary-const.md)、[比较分支融合对照](branch-compare.md)、[条件与一元融合对照](condition-fusion.md)、[通用条件窥孔对照](generic-branch-peephole.md)、[内建数值快路径对照](builtin-fast-paths.md)、[数组访问对照](array-access.md)、[数组写入对照](array-write.md)。 | 两个操作数都是 Number 时才走数值快路径；非字面量右侧保持 `Binary`。条件融合只用于比较/逻辑/取反条件，单用途窥孔仅在结果没有其他读者且分支不是控制流目标时启用。数组快路径只处理普通数组的自有元素和虚拟长度；缺失元素、访问器、原型链、Proxy、TypedArray 与字符串属性回退通用路径。 |
| 加载或验证 | 评估复用已验证的程序对象；继续拆分模块初始化与结构校验。 | [`Vm::new`](../../crates/vm/src/vm.rs) 仍需验证构建、链接当前宿主并初始化模块；不要用绕过校验换启动收益。 |

已做[独立加载实验](bytecode-loading.md)：函数引用索引未达到启用门槛。摘要已从 SHA-256 改为 xxh3-128，再改为 bincode 固定整数小端编码 + xxh3-128 流式哈希；产物也从 JSON 改为带 `BUILD_FORMAT_VERSION` 的 bincode 容器。构建身份校验约 0.55 ms，产物从 4.14 MB 降到 0.80 MB，解码从 15.3 ms 降到约 0.75 ms；React 首提交的“解码 + 启动准备 + 初始化”合计从约 18.8 ms 降到约 4.1 ms。现在模块初始化约 1.56 ms、结构校验约 0.89 ms，是剩余主要成本；单次冷加载的下一步应测复用已验证程序对象。多 VM 场景单独测同一收益，并保留完整的产物校验和快照的精确构建匹配。

实际应用剖析可用于选择热块和函数版本，不能替代类型证明或守卫；`.d.ts` 也只用于静态链接，不是运行时类型证明。跨挂起内联、对象标量替换、原生 AOT 暂不列入实施顺序，直到测得的收益值得增加状态重建成本。

## 4. 正确性与交付门槛

- **异常和恢复是一等 CFG 边。** 异常边看到的是正常目标写入前的值，由 handler 注入异常值。`await`、`yield` 的保存集合分别减去每条恢复边自己的注入目标，再取并集；生成器首次进入单独处理。挂起中的 `finally` 必须保留待完成状态。已兑现 Promise 的 `await` 仍经微任务恢复。
- **以证明约束变换。** 结果无用不代表可删；属性读取、类型转换、调用可能执行脚本或抛错。数值折叠和专用化保留 `NaN`、`-0` 与 BigInt 的语义。若使用动态守卫，失败必须在快路径产生副作用之前回退。
- **用基线做差分。** 同源脚本运行基线和优化产物，比较返回、抛错、宿主调用与微任务的可观察结果。两份产物分别用自身的 `Build` 快照往返，比较继续运行后的结果，不对比快照字节。用现有 `.js` 用例补语义边界，用 `e2e` 补恢复边、槽表、堆身份与错误拒绝用例。
- **精确构建匹配不变。** 不兼容字节码改动提升 `BYTECODE_VERSION`；只有快照记录形状变化才提升 `SNAPSHOT_FORMAT_VERSION`。保留旧快照对应的原始 `Build` 及兼容运行环境；同源重编译不保证 `build_id` 相同。基线编译路径用于性能及语义对照，不用于替换快照对应的构建。
