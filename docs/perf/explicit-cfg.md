# 显式 CFG：架构评估与优化计划

基于 `f5773fa`。这是实施计划，不是性能报告；当前契约见[内部契约](../internals.md)，历史数据见[第一批字节码优化对照](bytecode-optimization-round1.md)。

## 架构评估

- 保留可变逻辑寄存器 CFG。异常与挂起恢复已经进入数据流；现阶段的优化不依赖 SSA。
- 降低仍发射线性指令、回填 PC，再由 `FunctionCfg::from_lowered` 解码为块；布局仍把普通分支的一侧视为相邻块。先约束 CFG 变换，再逐步把普通分支和布局解耦。不一次性重写 lowerer。生成器首次入口、`yield` 的 `next` 相邻性及 `throw` / `return` 入口独占性由现有 VM 契约约束，不随普通块重排改变。
- 保存集合只依赖恢复目标的块入口活性：每条边先减去自身注入槽再取并集；生成器首次进入取完整活性。可在布局前计算，布局后再按最终顺序流式收集瞬时槽区间，避免物化整份逐 PC 活性表。
- CFG 当前保守地给可抛点添加所有覆盖 handler，VM 只选择优先级最高的一个。后续可单独提高精度；异常传递仍使用指令写入前的状态，不能与挂起拒绝边混用。

## 实施顺序

1. **CFG 校验与普通跳转清理。** 验证目标有效、生成器专用入口不被普通控制流进入、异常 handler 不保护自身。保持源块顺序和现有字节码编码；清理普通直跳链和跳向下一块的无条件跳转，无副作用且同目标的条件可省略。恢复落点、异常入口与生成器边界不参与普通跳板折叠；不能跳过可能执行 JS 转换或抛错的测试。
2. **扩展常量折叠和指令选择。** 从原始值的严格比较、已证明为 Number 的少量运算和现有 `BinaryConst` / 比较分支开始。验证 `NaN`、`-0`、BigInt 及转换顺序；不同完成种类在 `finally` 合流后不能强行折叠。
3. **评估挂起后重建字面量。** 仅重建可证明不变且无需执行脚本的廉价值。分别衡量保存值数、快照字节数和恢复后的额外分派，不以槽数推断端到端恢复时间。
4. **按剖析改进编译成本及槽分配。** 若活性全图扫描或逐绑定声明分析显著，再评估前驱工作队列、密集寄存器集合、批量声明分析。若帧大小有实测压力，再评估瞬时槽区间拆分；维持持久槽不复用。

## 验证与度量

- CFG 与布局的回归测试同时覆盖普通跳板、分支条件的转换副作用、异常保护和恢复落点；语义覆盖 `await` 拒绝、挂起中的 `finally` 与生成器的 `next` / `throw` / `return`。
- 以当前编译器与 VM 为新对照，不引用历史实验当作本次收益。复用[基准入口](performance-baseline.md)：React、数值/分支看静态代码和动态分派，挂起负载看 `saved_values` 和续跑；离线编译单独取时与峰值 RSS。只有变化稳定超过自然波动时才声称有耗时收益。
- 对照产物各用自己的 `Build` 做快照往返，比较恢复后可观察结果，不交叉恢复。仅改编译结果不改变字节码或快照格式；同源重编译仍可能改变 `build_id`。
