# 字节码加载实验

本轮只改 `Build::validate` 的函数引用查找：以按函数 ID 建立的 `BTreeMap` 取代线性扫描，复用模块校验已收集的初始化函数 ID 集合。查找支持稀疏、乱序 ID；校验项、字节码、构建摘要与快照格式不变。不把这个改动与编译 pass 或产物编码混在一起测。

## 函数引用索引：不启用

基线是 `987268d`，实验版在该提交仅应用[索引补丁](bytecode-loading/indexed-validation.patch)。按[基线复现命令](performance-baseline.md#复现)编译未插桩的 release bench，在 Apple M2（24 GiB）、macOS 27.0.1（26A434）、Rust/Cargo 1.99.1 上运行。A 批按基线 → 索引，B 批逆序；每个二进制各在独立进程预热 2 次、采样 9 次。[原始样本](bytecode-loading/)中，10 个负载的 `build_id`、产物字节数、静态指令数及帧槽数均一致。两版都通过基准的首次执行、稳态结果及各自快照续跑检查。

| 指标 | A：基线 → 索引 | B：基线 → 索引 |
| --- | ---: | ---: |
| React 首提交：启动准备中位数 | 17.086 → 16.900 ms | 17.083 → 16.893 ms |
| React 首提交：启动准备样本范围 | 16.955–17.514 → 16.747–17.285 ms | 16.984–17.262 → 16.725–17.409 ms |
| React 更新：启动准备中位数 | 17.066 → 16.963 ms | 17.122 → 16.916 ms |
| React 更新：稳态 5 次中位数 | 10.826 → 10.821 ms | 10.847 → 10.798 ms |

React 首提交的启动准备两批都降约 1.1%，但样本范围重叠，其他阶段也有同量级波动；例如未改动的 React 解码在实验版两批都慢约 0.5–0.6%。四个挂起负载的 `restore` 未见稳定改善。现有数据不足以启用额外的校验索引；补丁仅保留用于复现，没有合入验证路径。

## 启动准备分项

去掉索引后，用同一基准新增的计时点采两批（`phases-a.csv`、`phases-b.csv`），每批预热 2 次、采样 9 次，不启用运行时计数。逐样本核对三个子项之和等于 `startup_prepare`，10 个负载的产物与实验基线一致。以下是 React 首提交的中位数：

分项时钟只在 `Vm::new_profiled` 的启动路径读取；普通构造和恢复不采集这些计时。

| 阶段 | A | B |
| --- | ---: | ---: |
| 产物解码 | 15.39 ms | 16.17 ms |
| 启动准备合计 | 17.17 ms | 17.63 ms |
| 　构建身份校验（版本、JSON 序列化、SHA-256） | 15.90 ms | 16.28 ms |
| 　字节码结构校验 | 0.90 ms | 0.97 ms |
| 　宿主链接及 VM 准备 | 0.35 ms | 0.37 ms |
| 模块初始化 | 1.58 ms | 1.65 ms |

构建身份校验约占启动准备的 92–93%。当前计时不区分 JSON 序列化和 SHA-256 的各自耗时，也不能把这个比例外推到快照恢复。下一项加载实验应分别比较一次性冷加载与同一产物启动多个 VM：前者先拆分序列化与哈希，后者测复用已完整校验的不可变程序对象；每个 VM 仍须链接当前宿主并完成各自的初始化或快照校验。
