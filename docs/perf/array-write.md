# 数组元素写入快路径

数组数字索引写入此前先做键转换，再进入通用 `set_property`：沿原型链查描述符、处理访问器/只读属性/扩展性，最后写入数组元素表。本轮对最常见的“更新已有可写数据元素”增加局部快路径:

- `SetMember` 的键是 Number 且接收者是普通数组时，直接调用 `ArrayObject::set_existing_index`。
- 只更新已有、可写的 `Property::Data` 元素；重复写入不会修改 `length`，也不触发原型链查询.
- 空洞、缺失索引、新元素创建、访问器、只读元素、非数组接收者、字符串/负数/小数/超大索引全部回退原来的通用赋值路径.
- `length` 写入未改；扩展性、只读 `length`、原型 setter 和严格模式错误仍由 `set_property` 处理.

没有新增字节码指令，产物大小、静态指令数和 `BYTECODE_VERSION` 均不变；`SNAPSHOT_FORMAT_VERSION` 也不变.

## 环境与结果

父提交 `82039c4` 在独立 worktree 中构建, 加入相同的 `array-write` 工作负载；最终版为当前工作树. 两版各跑 A–E 五批, 每批 `--samples 5`, 取中位数. 复现:

```sh
cargo bench -p yield-harness --bench baseline -- --samples 5
```

## 边界

- 快路径仅在元素已经存在且描述符是可写数据属性时生效；命中后不需要键字符串、描述符查询或原型链遍历.
- 新索引仍由通用路径完成 `length` 增长、只读 `length` 拒绝、不可扩展拒绝和原型 setter 查找.
- 访问器元素仍调用 setter；只读元素仍按严格/非严格上下文抛错或返回 `false`.
- `Proxy`、TypedArray、字符串接收者和其他对象不进入该快路径.
- 该优化只影响运行时赋值，不改变新增索引、数组 `length` 赋值或快照内容.
