# 第一批字节码优化对照

基于 [性能基线](performance-baseline.md) 的 10 个负载，分别测量 CFG 常量/复制传播及静态属性键。两项都与本轮重跑的 `1e03b4a` 比较，未将两项叠加。原始数据见 [计时、诊断计数和峰值 RSS](bytecode-optimization-round1/)。

## 对照配置

| CSV 前缀 | 构建 |
| --- | --- |
| `base` | `1e03b4a` |
| `cfg` | 在 `1e03b4a` 仅应用 `57e20b1` 的编译器源码差异：`git diff 57e20b1^ 57e20b1 -- crates/compiler/src/ \| git apply` |
| `keys` | `61552b8`，仅启用 `GetMemberConstKey` |

同一台 Apple M2（8 核、24 GiB）、macOS 27.0.1（26A434）、Rust/Cargo 1.99.1、同一依赖锁及 release bench profile。按基线报告中的 `cargo bench --locked` 命令构建，在独立进程采样：A 批按 `base → cfg → keys`，B 批逆序，各预热 2 次、采样 9 次；计数用单独的诊断二进制。各变体的两批计时与计数使用相同 `build_id`。挂起负载各自使用本变体的 Build 恢复，检查续跑结果，不跨产物恢复。RSS 每变体每负载一个独立进程样本。

## 两项的独立收益

百分比为各批计时中位数相对本批基线的变化（负值为耗时下降）；动态分派是同一 VM 稳态 5 次的总数。

| 指标 | 仅 CFG | 仅静态属性键 |
| --- | ---: | ---: |
| React 更新：稳态耗时 A / B | −5.1% / −1.2% | −4.6% / −1.0% |
| React 更新：动态分派（基线 220,875） | 209,470 | 203,635 |
| React 产物大小（基线 4,614,572 B） | 4,410,943 B | 4,344,041 B |
| React 更新：产物解码 A / B | −9.4% / −5.1% | −10.7% / −6.2% |
| React 更新：启动准备 A / B | −7.8% / −4.3% | −9.3% / −4.4% |
| React 更新：离线编译 A / B | +9.5% / +13.0% | −7.2% / −3.7% |
| 数值/分支：动态分派（基线 266,320） | 266,300 | 266,320 |
| 数值/分支：稳态耗时 A / B | −0.3% / −0.1% | +0.1% / +0.5% |
| 静态属性：动态分派（基线 66,640） | 66,630 | 61,515 |
| 静态属性：稳态耗时 A / B | −0.9% / −1.6% | −3.5% / −2.7% |

- **CFG** 默认启用：React 产物缩小 4.4%，两批解码和启动准备均改善；数值负载的分支主要由运行时值决定，未见稳态加速。React 编译峰值 RSS 的两个负载样本为 47.64–47.94 MiB，基线为 47.81–48.05 MiB。离线编译时间增加，但不进入运行时路径。
- **静态键**默认启用：静态属性负载少 5,125 次分派、属性探测仍是 15,365 次、静态帧槽总数仍是 9。证据支持减少键的物化和分派，不支持属性查表本身变快。React 静态帧槽总数从 4,864 降到 4,821，CFG 单独降到 4,806。
- **波动**：React 更新基线的两批稳态样本范围分别为 11.13–11.82 ms、11.06–11.26 ms；B 批两项优化的采样区间都与基线重叠，不把 React 的稳态差值当作确定的加速幅度。静态属性 B 批范围从 1.719–1.766 ms 变为 1.670–1.736 ms（仅静态键）。四个挂起负载中，恢复中位数最大回退为 +0.7%（静态键、`await` 成功、B 批），不据此宣称恢复收益。

`GetMemberConstKey` 将字节码版本升为 47，快照记录格式不变。原来的 Build 与对应快照仍须用兼容的 VM 恢复。两项合并后通过工作区的语义与恢复测试；独立收益不应相加。
