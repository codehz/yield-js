# 已实现内容

当前实现由代码推导的覆盖范围清单。语法子集与未覆盖项见 [`docs/gaps.md`](gaps.md)。

- 字节码 **58** 将源码模块图、声明与求值函数、入口、可选 preload、最终导出目标、生成器恢复表、标签模板表和 BigInt 常量纳入构建摘要。摘要输入使用 bincode 固定整数小端编码，哈希为 xxh3-128；编码选项或 crate 版本变化会改变所有 `build_id`。构建产物使用 `Build::to_bytes` / `Build::from_bytes` 的 `YIELDBLD` + `BUILD_FORMAT_VERSION` + bincode 固定整数小端容器；JSON 往返仅用于测试和调试。加载时校验模块索引、可达性、绑定归属、getter、指令结构，以及生成器函数的种类、唯一启动边界、三个恢复落点、槽范围与升序 `saved_slots`；`async function*` 可同时拥有 `await` 恢复表和生成器恢复表，两张表各自独立校验；普通控制流不得进入 `throw` / `return` / 正文入口，坏产物返回 `InvalidBuild`。
- 标签模板由编译器直接降级为普通调用：标签引用按成员/调用语义求值并保留接收者，随后按调用点取得缓存的模板对象，最后从左到右求值替换表达式并以原值传入，不做字符串转换。每个调用点在 VM 启动时分配一个模板对象：冻结的 cooked 数组、冻结的 raw 数组，以及不可写、不可枚举、不可配置的 `raw` 自有属性；非法转义在 cooked 数组中是 `undefined`，raw 保留源码文本。模板对象是 GC 与快照根，快照格式 **61** 按构建的调用点顺序保存对象身份；恢复拒绝数量不符、重复、未冻结或内容不匹配的记录。
- 严格 ESM 支持本地命名导出：`export function`、`export async function`、`export var` / `let` / `const`、`export { local }` 和 `export { local as publicName }`。默认导出也已支持：`export default <表达式>`（语句处求值一次，不求值不生效）、`export default function`（含匿名与 `async`，按函数声明提升并在模块入口初始化）、`export default class`（含匿名；具名类沿用类声明的语句处初始化与局部名字），以及保留活绑定的 `export { x as default }`（含宿主导入绑定）。具名 default 声明把局部 id 投影到公开名 `default`，不自动导出原名；同一模块只能有一个 default（解析期拒绝）。`Vm::new(build, host, VmOptions::default())` 验证构建和导入后执行一次模块初始化，再排空微任务。宿主通过 `Vm::get_export` 读取公开名对应的当前绑定值，`Vm::start` 读取并调用该值；未导出的声明（包括名为 `run` 的函数）对宿主不可见。恢复保留活绑定，不重跑初始化。
- `Compiler::compile(Project)` 用同步 `ModuleResolver` 链接可达源码，并按注册顺序运行源码、图和 Build 转换。`Project::from_directory` 使用 `NodeResolver`，从引用模块向根目录逐级搜索 `node_modules`，只解析包 `exports` 的精确子路径和 `import` / `default` 条件。`MemoryResolver` 保留根相对路径规则。解析返回 `ResolvedModule`：规范模块 ID 加上该定义模块的框架标记；`NodeResolver` 把 `node_modules` 内定义的模块（含包 `exports` 目标、嵌套依赖和包内相对导入）标为框架，`MemoryResolver` 从不标记。标记只决定是否为该模块生成 Error 栈位置，不改变解析、链接或运行语义。`Compiler::from_dts` 独立读取宿主模块与值导出清单。ESM 支持具名、默认、命名空间和副作用导入，以及具名、星号和命名空间转导出；星号不传递 `default`，不同最终目标的同名导出从命名空间排除。
- 显式 `NodeResolver::web_production` 按 `browser` → `import` → `production` → `default` 选择包导出条件。无 `exports` 时支持 `main` / `index.js` 与包内子路径。静态 CommonJS 在发现依赖前转换为同一 ESM 图中的 facade 和惰性 factory；字面量 `require` 共享模块缓存，循环可读到部分导出，ESM 具名导入取得初始化后的属性快照。默认 ESM 解析与活绑定不变。
- 源码和图转换可用 `ParsedModule::program_mut` 原地修改固定版本的 Oxc AST。源码转换产生的导入参与依赖发现；图转换后重新校验依赖并计算链接绑定，不直接公开链接表。
- `.jsx` 模块使用自动 JSX runtime；编译器将元素与片段转换为 `<jsx_runtime>/jsx-runtime` 的静态导入和 `jsx` / `jsxs` 调用。默认包为 `react`，不依赖 `React` 全局或 `createElement`。
- `import("literal")` 在编译期解析为依赖；目标模块按依赖图提前求值，每个模块仍只求值一次。每次执行该表达式都会返回一个新的已兑现 Promise，值是目标模块的命名空间，不执行 thenable 同化。
- 模块内裸缺名的 `typeof` 折叠为 `"undefined"`；仅在当前模块探针确认缺名后，纯比较、否定、条件表达式与逻辑短路才剪除静态不可达子树。被实际执行到的同一缺名读取、调用、构造或写入在对应求值点抛出可捕获的 `ReferenceError`，安全的 `typeof` 仍返回字符串；不做跨函数调用图或跨模块传播。
- VM 在执行任何模块体前创建全部模块环境和命名空间，并初始化提升函数和 `var`。依赖优先、按源码声明顺序求值；循环回边跳过，共享模块只执行一次。读取另一模块未初始化的词法绑定抛出可捕获的 `ReferenceError`。命名空间无原型、不可扩展，按导出名排序，通过只读 getter 提供活绑定。
- 先求值 preload 的可达子图，再把 preload 根的链接导出安装为 `globalThis` 的只读活绑定；裸 preload 名只在不属于该子图的 entry 依赖中可用（包含 entry 本身）。模块之间不排空微任务。`Vm::get_export` 和 `Vm::start` 只使用 entry 的链接导出。快照 **61** 保存模块环境与命名空间根，恢复不重跑初始化；诊断入口校验模块根、槽归属与 getter。
- 快照支持原有 JSON 和二进制 `YIELDSNP` 容器（`Snapshot::to_bytes` / `from_bytes`）。两者解码成同一 `Snapshot` 记录；恢复仍匹配精确构建和宿主绑定。`Vm::restore` 默认不重复审计堆图；开发和诊断可用 `RestoreOptions::validation` 选择 `SnapshotValidation::Full`。两种模式都仅用于可信、未经篡改的 VM 镜像。
- 静态宿主模块支持 named（含别名）、default 和 namespace 导入。导入绑定只读，宿主导出函数是 VM 自有的函数对象；命名空间由 VM 创建，其导出属性不可写、不可配置。Rust 宿主用 `#[host_module]` / `#[module_exports]`、`#[host_class]` / `#[methods]` 和 `#[operation]` 声明绑定，`host!` 一次性链接，并在展开时按声明的 `dts` 文件校验每个声明的值名（缺名即编译错误，实现可更宽，纯类型声明不产生要求）。`#[function]` / `#[method]` 的 `async fn -> JsResult<HostStep>` 可用受限 CPS 语法表达 guest 调用续接，不创建 Rust Future。VM 链接期校验模块、导出种类，把类原型、实例槽、payload、模块状态和 operation 的持久记录保存在 VM 的堆与快照中；运行时按声明 ID 分派，不按字符串查表。
- 具体的 `Host` 不可克隆；新建和恢复按值接管 `Host`，执行和投递不再传入宿主。`host!` 也支持仅注册服务，空宿主用 `Host::default()`。宿主和服务实例只在运行时存在，不进入快照。嵌入方通过 `vm.bind_service::<T>()` 解析并只读借用确切类型的服务；服务支持 `Rc`，在工作线程执行的服务由自身 trait 声明线程约束。
- `host!` 只链接选中模块在 `#[host_module]` 中声明的类与 operation。链接按 Rust 类型去重；不同类型的重名冲突仍报错，类型身份不进入指纹或快照。
- `host!` 将 `Type => value` 生成类型化字段并整体擦除；同一类型（含别名）重复注册报错。模块、类和 operation 直接用 `services = [name: Type, …]` 声明必需依赖，缺失时报链接错误。生成的访问器读取链接期解析的字段槽，不按类型查表或 downcast。
- 每个注册模块的快照状态包括 `Js` / `JsList` 槽和无 schema 版本的 codec 字节。新建用 `FromServices`（`Default` 类型自动实现），恢复只用 `Decode`。模块、类 payload 及 operation 共用 `Encode` / `Decode` 字段协议。`#[host_module]` 剥离 VM 槽后，仅为空类型自动补默认初始化和空 codec。快照格式 **91** 删除了模块状态记录中的 `schema` 字段。
- 宿主类实例共享 VM 所有的类原型；方法入口校验内部类标签，裸调用或 `Object.create(prototype)` 伪造接收者抛出可捕获的 `TypeError`。原型方法与访问器可被脚本改写或删除，快照保存改写结果。实例可带隐藏的 `Js` / `JsList` 槽和可选 payload；槽是强引用边，不触发 getter 或 Proxy trap，也不会出现在自有键或属性描述符中。带 `class` 的 `#[constructor]` 导出具有固定的 `prototype` 自有属性，支持 `new`、`instanceof` 和静态继承。
- 宿主类成员名可以是字符串或由 `WellKnownSymbol` 显式声明的 well-known Symbol；原型方法、访问器与构造函数值仍由 VM 持有。声明 `#[host_class(parent = Base, ...)]` 时，父类原型成为子类原型的原型，槽布局按父类在前合并；基类方法与访问器接受派生实例。payload 仍属于具体实例类。脚本类可继承宿主构造器：只对本次构造中与声明类匹配的宿主分配使用派生原型，不修改其他分配或构造器返回的替换对象。宿主接收者仍校验声明类标签；脚本私元素与宿主槽和 payload 独立，均可跨快照恢复。
- 宿主异常是普通宿主类实例：`#[host_class(builtin_parent = Error | DOMException, ...)]` 声明标准基类，宿主子类继承其品牌。`Error.isError` 按实例底层形态识别，不读写脚本原型，也不触发 getter 或 Proxy trap；`instanceof` 仍遵循脚本原型链。构造器必须使用 `new`；`CallCx::alloc` 使用基类默认值，`alloc_with_super` 显式传入基类实参，转换异常原样传播。宿主异常以值抛出；`Vm::alloc_error`、`CallCx::alloc_error` 和 `JsError::new_error` 仅接受内建 `ErrorKind`。快照格式 **94** 使用普通宿主原型、实例、槽及 payload 记录，Full 恢复校验实例形态，不重新推断原型或生成栈。宿主实例仍不能经 `structuredClone` 克隆。
- `JsValue` 是宿主边界句柄：值携带 VM 代际与调用 ID，跨调用保存的旧句柄在写槽时产生 `HostFault`，而不是可捕获脚本异常。payload codec、模块初始化与 operation driver 通过当前的 `&Services<'_, Owner>` 读取已链接的字段。服务不参与绑定指纹；恢复仍检查镜像实际需要的能力。
- 宿主函数和方法用 `HostStep::Suspend` 交还受校验的请求；VM 在当前 `CallCx` 结束后同步执行 guest 调用或 GC。恢复使用新的调用 ID、原始 `this` 和显式保存的值。后台宿主任务还可等待外部 operation；其完成入队，不在投递调用中执行脚本。旧调用创建的请求不能重放。
- 只读 `Inspect` 可识别真正的 RegExp、读取其内部模式和标志，并用已编译的模式从索引 0 检查匹配。检查不访问 `lastIndex`，也不执行脚本定义的 `exec` 或 `test`。
- 每个 `HostModule` 类型声明模块身份和每 VM 一份的状态。导出通过 `ModuleCx` 只访问本模块的状态；JS 引用写入状态槽，非 JS 数据经 codec 编码。每个模块的状态都进入快照，槽是持久根。
- `test` 宿主模块提供 `expect(actual)` 返回的 `Matcher` 实例、共享原型方法 `toBe` / `toEqual` / `toBeTruthy` / `toThrow`、`value` 访问器，以及 `assert(condition, message?)`、`bind(label)`、`wait(label)`、`inspect(value)`、`seed()`、`setLabel(node, label)`。成功返回 `undefined`；失败作为可捕获的脚本异常抛出。结构比较通过只读 `CallCx::inspect` 视图遍历普通对象/数组的自有可枚举数据属性，不运行 getter。
- VM 全局 `console` 实现 [WHATWG Console](https://console.spec.whatwg.org/commit-snapshots/1b44c2c39405ff96ad0807eec765d8fb861d07b8/) 的 19 个方法。Printer 同步把结构化参数、分组路径、表格、跟踪帧或清屏事件交给可选的 `console`（`ConsoleSink`）；不读取 getter 或代理 trap 来生成预览。没有 sink 时，只有实际打印才抛 `NotSupportedError`。快照格式 **87** 保留计数、相对计时起点与分组标题，不保存或重放历史输出。
- `test` 的 `spawnDelayedTask` / `cancelDelayedTask` 演示可取消的宿主后台任务；`sleep` 直接返回原生 Promise。两者用同一无墙钟 operation driver，接受有限非负的 `u32` 整数毫秒。宿主 operation codec 保存剩余时长，与全局脚本定时器的记录无关。
- 可选服务 `time`（`TimeService`） 提供有符号 Unix 毫秒与 IANA 时区标识，供 `Date` 和文件时间戳读取；未注册服务时回退到固定的 `DummyTimeService`（epoch 0，`Etc/UTC`），保证无宿主时间也可确定地运行。测试宿主读取同一 `FakeClock`，并在超出 ECMAScript 日期范围前拒绝时钟变更；演示宿主注册系统时间与启动时读取的系统时区的 `SystemTimeService`。
- `toThrow` 同步调用 thunk 一次；省略模式或传 `undefined` 时接受任意抛出值，字符串按 UTF-16 码元检查子串，RegExp 做无副作用的匹配检查。模式匹配只使用抛出的字符串或对象自有的字符串数据属性 `message`；真正的 Error 缺少该属性时按空串处理。Error 内部标记可快照恢复，不依赖原型链。
- 同步生成器 `function*` 与 async generator `async function*`（声明、表达式、对象与类的方法）在调用时初始化形参后立即返回生成器对象，正文只在 `next` 时执行；异步生成器的调用不分配结果 Promise。`GeneratorStart` 是独立的调用期边界，只捕获正文入口的活槽；每次 `yield` 生成一个 `GeneratorEntry`，分别给出 `next_pc` / `throw_pc` 的注入槽和 `return_pc`，`LoadGeneratorReturn` 只在该落点读取本次恢复传入的完成值，待完成值不进入全局状态。生成器函数不可构造，其实例原型是函数的 `prototype`（非对象时回退对应的共享生成器原型：同步与异步生成器共用各自的 `generator.prototype` / `asyncGenerator.prototype`，两者不互相继承）。
- 同步与异步生成器的正文均可直接以 `for (;;)`、`while` 或 `do…while` 开始（前置空语句也不影响）。如果循环头紧邻 `GeneratorStart`，编译器为首次恢复生成独立的跳转入口，循环回边只跳到实际循环头。
- `yield*` 降为显式委托循环。同步委托只覆盖同步迭代：取得迭代器并缓存 `next`，首次传 `undefined`，此后把恢复值传给委托；`throw` / `return` 完成先动态读取委托的同名方法并以委托为 `this` 调用。委托结果对象原样交给消费者，不重复包装——`done` 为假时只在真正推进时才读 `value`；`done` 为真时用其 `value` 作为 `yield*` 表达式的值，`return` 完成则沿外层 `return` 路径穿过 finally。缺 `return` 方法时传播传入的 `return`；缺 `throw` 方法先用无参 `return` 关闭（关闭自身的异常优先），再抛可捕获的 `TypeError`；`null` / `undefined` 视为方法缺失，其他不可调用值和非对象结果同样抛 `TypeError`，取方法、调用或读属性抛错按当前词法处理且不额外关闭。
- async generator 的 `yield*` 共用同一条委托循环：先读取 `[Symbol.asyncIterator]`，只有 `null` / `undefined` 才回退同步协议；原生异步分支把调用的结果和每个方法调用的结果都先经隐式 `await` 同化，再校验为对象，然后才读 `done` / `value`。同步回退先验证同步结果对象，再读 `done` / `value` 并只对 `value` 做隐式 `await`，不把整个同步结果当作 thenable。回退标志是普通活跃寄存器，跨挂起保存。委托未结束时异步 yield `value`；`done` 为真时按当前 `next` / `throw` 或 `return` 路由，委托 `return` 返回 `done: false` 时继续委托循环。缺 `throw` 时若有 `return`，先无参调用并等待关闭、验证对象后再抛 `TypeError`；获取器、不可调用方法、非对象结果和拒绝都进入脚本异常路径。
- `for await…of` 降为显式循环：先读 `[Symbol.asyncIterator]`，只有 `null` / `undefined` 才回退 `Symbol.iterator`；原生异步分支先 `await` 方法结果再校验为对象，同步回退先校验同步结果对象并只对每轮 `value` 做隐式 `await`；`done` / `value` 按需惰性读取。头部与正文的 `await` / `yield` 都是普通挂起点。提前退出（`break`、`return`、正文抛出）调用并等待 `return()`，关闭失败（getter 抛出、拒绝、非对象结果）被丢弃，原完成照常进行；正常耗尽不关闭。回退标志、迭代器与缓存的 `next` 都是跨挂起与快照恢复的普通活跃槽。
- 生成器函数与 async generator 函数的内部原型分别是 `%GeneratorFunction.prototype%` / `%AsyncGeneratorFunction.prototype%`（继承 `Function.prototype`），其自有 `prototype` 指向共享的 `%GeneratorPrototype%` / `%AsyncGeneratorPrototype%`；函数实例的 `.prototype` 以对应共享原型为原型。
- 生成器对象是普通对象加一份暂停帧（状态、函数 ID、环境、按入口 `saved_slots` 排列的值）。`next` / `throw` / `return` 是共享生成器原型上的内建方法：恢复前取走保存状态并标记执行中，同步生成器被重入时抛可捕获的 `TypeError`；`next` 同步返回 `{ value, done: false }`，正文返回或落底给出 `done: true`，未捕获异常使生成器完成并原样抛出；已完成状态不再持有帧。`[Symbol.iterator]` 返回 `this`，因此 `for…of`、数组展开等现有消费路径不需要生成器特判，`finally` 中的 `yield` 保留待完成的 `return`。
- async generator 对象在同一份记录上另有 FIFO 请求队列（完成种类、参数、请求 Promise）和等待状态，且只由异步生成器使用；`[Symbol.asyncIterator]` 返回 `this`，没有同步迭代入口。三个请求方法先入队再驱动，队首就是进行中的请求，执行中重入只追加而不抛错。`yield` 兑现队首 `{ value, done: false }`，正文返回或落底兑现 `done: true`，未捕获脚本异常使生成器完成并拒绝该请求；`await` 挂起时请求留在队首、生成器标为等待，恢复的是同一正文而不是新请求。首次 `next` 忽略参数，未启动的 `throw` / `return` 不进入正文。已完成后 `next` 立即兑现 `{ value: undefined, done: true }`，`throw` 原样拒绝，`return` 先经可持久化的 Promise reaction 同化参数再兑现 `done: true`，期间后续请求不越过队首；参数准备或同化失败只拒绝该请求。`yield`、`return` 的操作数以及挂起处注入的 `return` 参数都先经隐式 `await`，拒绝走词法 `catch` / `finally`。
- 生成器帧、异步请求队列和续体目标参与运行期 GC 与快照：暂停的环境、保存槽、请求参数、请求 Promise 和续体目标都是强引用边，完成后释放；快照格式 **61** 保存普通对象身份、原型、状态、函数 ID、恢复表索引、按表排列的槽值、有序请求队列和续体目标种类，不写瞬时槽或运行时 PC。恢复在发布 VM 前拒绝执行中状态、非生成器函数、非法表索引、值数不符、重复的请求 Promise，以及无主或重复关联的等待续体 / 关闭 reaction。
- 单名 `using` / `await using` 接受初始化器，初始化绑定前捕获释放方法，无隐式等待初始化器。函数、块和模块求值的清理由隐式 `finally` 路由；同步模块及同步函数不允许 `await using`。没有资源声明的作用域不分配清理列表。编译器使用私有内建登记和单步清理，异步等待沿普通 `Await` 保存待完成值与清理状态；恢复不会重做登记或已执行的释放。`yield` 不退出作用域，生成器恢复注入的 `return` / `throw` 才按完成路径清理。
- C 风格 `for` 的 `using` / `await using` 头在整个循环退出时释放；`continue` 不结束头部资源的生命周期。`for…of` 和 `for await…of` 的单名资源头每轮先登记、再初始化绑定和执行正文，当轮清理先于迭代器关闭。迭代方式独立于释放 hint，`for…in` 不允许资源头。模块顶层 `using` 在本模块求值返回前完成清理，不在实例化、恢复或 VM 销毁时运行。
- `SlotKind::{Transient, Persistent}`；`ResumeEntry` 保存 `fulfill_pc`、`reject_pc`、结果槽和升序 `saved_slots`。
- `yield-blitz` 通过 `BlitzSession` 持有 VM 与文档；版本化 DOM payload 随 `yield:dom` 模块状态快照，恢复时直接重建 Blitz 节点树、脱离子树及包装索引，不重跑模块初始化。快照保留 JS 节点、闭包、expando 与监听器身份，恢复后脚本可继续更新树；`render_module` / `render_fixture` 仍提供执行后移交文档的一次性入口。锁定 React 首屏 fixture 使用 `BaseDocument` 并由 Blitz shell/Vello 显示。
- `BlitzSession::click` 和原生窗口的主键点击共用 VM 的 `EventTarget` 派发：向当前文档的元素发送可信、可冒泡、可取消的 `click`；取消会阻止 Blitz 默认动作。节点的事件父级用 VM 托管槽保存，随节点移动或脱离更新。快照恢复监听器、闭包和 React 计数状态，不重放原生输入；恢复后应从新文档取得目标，再投递下一次点击。
- 编译期 CFG 活性分析：每个恢复入口先扣除该入口的结果槽，再取并集作为 `saved_slots`；异常边参与活性。
- 不跨挂起点的值分配到瞬时槽，活性区间不相交的值可复用同一个瞬时槽；持久槽不复用。挂起时丢弃瞬时槽，恢复时只重建指定持久槽。
- 未导出且未跨函数共享的绑定在帧槽中；导出和闭包共享的绑定仍在堆环境，快照保留环境、闭包与对象身份。没有共享绑定且不创建闭包的调用不分配环境。
- 槽分配前在 CFG 上传播字面量和复制，折叠已知原始值的严格比较、少量双 Number 运算和已知真假值的分支，删除不可达指令并压缩挂起表。异常边使用目标写入前的状态，恢复边各自使注入槽的旧事实失效。随后重算活性，仅删除自复制和结果无用的纯槽写入（`Move`、`Const`、`Undefined`）；可执行的 getter、JS 转换和抛错操作仍保留。
- `for` 的 `let` / `const` 头（C 风格、`for…in`、`for…of`、`for await…of`）为每轮迭代建立独立环境。编译器按跨函数读写判定绑定逃逸：被嵌套函数读写的循环绑定复制到新环境并保留环境槽；未被捕获的绑定提升为帧槽，循环各轮复用同一槽，不再复制。循环体与 `update` 中的闭包仍保留各自迭代的值；C 风格 `update` 在新的迭代环境中执行，循环结束后恢复外层环境。若循环体内存在被嵌套函数读写的块级声明，每轮环境保留但绑定表为空，仅提供新单元格；否则整组 `SaveEnv` / `NewIterationEnv` / `RestoreEnv` 从字节码中删除，并重映射跳转、异常表、恢复表与生成器表的 PC。
- 函数声明提升；函数表达式、箭头函数、函数值成员调用。`this` 是隐式参数：方法调用传入接收者（给成员表达式加括号不改变接收者），普通调用传入 `undefined`，箭头函数沿词法链读取。
- 点属性、字符串字面量下标及无替换的模板字面量下标可降为 `GetMemberConstKey`，包括方法调用及可选链中的读取。VM 从常量池借用字符串，跳过键槽和键转换，仍走通用属性读取。加载时拒绝非字符串或越界的键索引。
- 二元运算的右侧为可入池字面量（含 CFG 证明的常量）时可使用 `BinaryConst`，直接从构建常量取右操作数；比较分支也可使用对应的常量变体。不调换操作数，可能执行 JS 转换的操作仍按原顺序转换。加载时校验槽和常量池索引。
- `if` / `while` / `do…while` / `for` 条件、条件表达式和 `switch` 的 `===` 比较直接降为 `BranchCompareFalse` / `BranchCompareTrue`；右侧字面量使用对应常量变体，不写布尔结果槽。`&&` 降为短路的假分支链，`||` 用真分支跳过右侧，`!` 直接使用 `BranchTrue`；双 Number 直接比较，其他类型复用通用比较和转换路径。数值一元运算（`-`、`+`、`~`、ToNumeric、`++`、`--`）在 `Number` 上直接执行，其他类型仍走对象转换和 BigInt 路径。
- 结果只被条件使用的 `Binary` / `BinaryConst` / `Unary` 会在 CFG 优化后融合为 `BranchBinary` / `BranchBinaryConst` / `BranchUnary`，删除结果槽写入；分支本身是控制流目标时保持原样。`Math` 单参数/双参数方法、`max` / `min` / `hypot` 和 `Number` 构造/静态方法对已经为 `Number` 的实参跳过通用 `ToNumber` 转换；其余实参仍走完整转换和错误路径。
- 数组元素读取对动态 Number 索引直接查 `ArrayObject::elements`；`.length` 走普通属性读取。元素缺失、访问器、原型链、Proxy 和稀疏数组的语义不变。已有可写数据元素的数字索引写入直接更新元素；缺失索引、空洞、访问器、只读属性和新元素创建仍走通用赋值路径。
- 变量声明（含命名导出）、函数与箭头函数形参、`catch`、`for…in` / `for…of` 左侧和 `=` 赋值均支持嵌套的对象与数组解构。默认值仅在读到 `undefined` 时求值，形参从左到右初始化。对象 rest 复制未匹配的自有可枚举键（含 Symbol），与对象展开共用复制规则；计算键只求值和转换一次。解构 `null` / `undefined` 抛出可捕获的 `TypeError`。
- `const` 声明正常初始化（含解构与 `for…of` 的每轮写入）。之后对该绑定写入时才抛出可捕获的 `TypeError`（`Assignment to constant variable.`）：包括普通、复合、逻辑赋值、自增减、解构赋值和闭包中的写入。逻辑赋值短路时不写入、不抛错；解构按赋值顺序在第一个实际写入的 `const` 目标处抛错，之前的副作用与写入保留。内层同名绑定按自身的声明规则处理；`const` 不冻结对象或数组。绑定的可变性在编译期解析，不需要写入快照。
- 函数与箭头函数支持 rest 形参（含解构模式）。每次调用把超出位置形参的实参收集到一个新数组；没有剩余实参时得到空数组。普通绑定和槽位的快照机制保留跨 `await` 使用的 rest 数组。
- 普通函数和方法按需创建严格模式的非映射 `arguments` 对象：它继承 `Object.prototype`，不是数组，包含所有实参的索引和不可枚举的 `length`，以原始 `Array.prototype.values` 为自有迭代方法。形参与索引的写入互不影响；不提供 `callee` 或 `caller`。默认参数可以读取它，箭头函数沿词法链读取，名为 `arguments` 的形参会遮蔽隐式绑定。此子集中的函数体 `var arguments` 复用已有的函数绑定，不为非简单形参创建独立的函数体绑定。对象身份和迭代位置可跨 `await` 恢复。
- 函数的 `length` / `name` 是不可写、不可枚举、可配置的自有数据属性。声明与显式命名的表达式保留名字；支持的匿名函数、箭头和类按绑定、默认值或属性键推断名字，不创建额外词法绑定。计算键只转换一次。脚本 `length` 统计首个默认形参前的位置形参（不含 rest）；内建和宿主函数使用各自声明的元数据。
- `Function.prototype` 可调用并返回 `undefined`，不可构造；它提供共享的 `call`、`apply`、`bind`、`toString` 和严格模式的 `caller` / `arguments` 访问器。全局 `Function` 的调用和构造都抛出 `TypeError`，不转换实参、不编译字符串。`toString` 返回 `function <初始名>() { [native code] }`，不读取公开 `name`，也不保留源码。
- `bind` 捕获目标当时的内部原型，依次读取自有 `length` 和普通 `name`；结果写入绑定函数的自有描述符，不随目标变化。绑定函数不自动创建 `prototype`，其目标、参数、描述符和初始显示名可跨快照恢复。
- 对象/数组字面量、计算属性键、简写方法（含 `async`）、getter/setter、成员读写、数组 `length` 与索引、复合成员赋值。数组字面量的省略项产生真正的稀疏空洞：只增长 `length`，不创建索引属性，`map` / `forEach` / `JSON.stringify` / `join` 等按稀疏语义处理；展开 `[...a]` 仍通过迭代协议将洞读成显式 `undefined`。`new` 创建实例并沿构造函数的 `prototype` 查找属性；自有属性优先，继承访问器中的 `this` 是实际接收者。简写方法不能用作构造函数。
- 对象字面量支持展开：按自有键顺序复制可枚举的字符串键和 Symbol 键，每次复制前重查描述符。来源 getter 以来源对象为 `this`，异常可捕获；结果总是自有数据属性，不调用目标 setter。跳过空值和无可枚举键的原始值；字符串按 UTF-16 索引逐码元复制。字面量在展开表达式中挂起时，已构建的属性可跨快照恢复。
- `in` 检查对象自身及原型链上的属性（包括 Symbol 键），不执行 getter；右操作数不是对象时抛出 `TypeError`。
- `instanceof` 从左到右各求值一次；右操作数必须是对象。通过普通属性读取 `[Symbol.hasInstance]`（包括继承的 getter 和 Proxy），非空方法必须可调用，以右操作数为 `this`、左操作数为唯一实参，结果转为布尔值，异常原样传播。方法为空时要求右侧可调用。共享的 `Function.prototype` 提供固定、不可枚举的默认方法：非可调用接收者返回 `false`，绑定函数对其目标重新查找协议，普通函数在左侧为对象时读取 `prototype` 并沿原型链比较；非对象 `prototype` 抛出 `TypeError`。
- `Reflect.get` / `set` 从目标查找属性，可显式指定接收者；省略时使用目标。访问器以接收者为 `this`，数据写入只更新或创建接收者的自有属性。对只读属性、缺少 setter 或不可扩展接收者的写入拒绝返回 `false`（同样的拒绝在严格成员赋值中抛出 `TypeError`）；键转换、访问器及数组长度检查的异常仍会抛出。`Reflect.has` 沿原型链检查而不调用 getter，`Reflect.getOwnPropertyDescriptor` 只检查自有属性。这四种操作都要求目标是对象。
- `Reflect.apply` 转发 `this` 和参数；`Reflect.construct` 与 `new` 共用构造路径，可指定 `newTarget`。两者都要求参数列表是对象，按 `ToLength` 处理 `length` 后依次读取索引，传播访问器和目标抛出的异常。普通脚本构造器、`Array`、`Map`、`Set`、`Object`、`String`、`Number`、`Boolean`、错误构造器及 `Promise` 支持构造；箭头、异步和方法不可构造。绑定函数仅在目标可构造时支持构造，前置绑定参数而忽略绑定的 `this`；若当前绑定函数自身是 `newTarget`，则向目标转发时替换为其目标，否则保留显式指定的 `newTarget`。`newTarget.prototype` 是对象时作为实例原型，否则沿用 `new` 的行为；脚本构造器返回对象时优先采用该对象。
- 普通函数调用中的 `new.target` 是 `undefined`；构造调用中是实际的 `newTarget`（含绑定构造器转发及 `Reflect.construct` 的显式目标）。箭头函数（含异步箭头）捕获外围函数的 `new.target`，普通嵌套函数有独立绑定。
- `class` 声明（含命名导出）和表达式按执行顺序创建可传递的构造器值；普通调用抛 `TypeError`。命名类每次求值捕获独立、只读的内层名字，外层声明仍可赋值。`extends` 在类定义时设置构造器及实例原型链。公共方法及访问器不可枚举，计算键只转换一次。静态块及字段按源码顺序运行；基类实例字段在构造器默认参数前定义为自有属性。
- 派生构造器不预分配实例。`super()` 使用构造器的当前父级和原始 `new.target`；成功后绑定 `this` 并初始化派生字段。箭头共享这次调用的 `this` 绑定。默认派生构造器直接转发实参；显式构造器的返回值在 `finally` 确定最终完成状态后检查。
- `super` 属性从方法定义时的 home object 的当前原型开始查找，读写及调用保留实际的 `this`。类的实例与静态方法、访问器、字段初始化器、静态块和对象字面量方法都支持该引用；嵌套箭头捕获它，普通嵌套函数不捕获。
- 私有字段、方法及访问器由 VM 安装在接收者自身上。每次类求值生成独立品牌；同名私元素不能跨品牌访问，静态品牌不继承，代理不转发私访问。字段按初始化进度逐个添加，私有方法和访问器在字段前安装。私元素不参与属性反射，`#name in object` 检查精确元素；快照只保留可达接收者的私元素，恢复不重跑初始化。
- `for…in` 支持声明、已有绑定、成员或解构模式作为目标。按每层自有键顺序枚举对象及其原型的可枚举字符串键，不读取属性值；尚存在的不可枚举自有键会遮蔽继承的同名键。进入每层时记录键，访问前重查描述符，跳过已删除的键；不会枚举进入该层后新增的键。原始值从各自的共享原型继续枚举；字符串先给出 UTF-16 索引，自有的不可枚举 `length` 遮蔽原型同名键。`null` 和 `undefined` 不迭代。枚举位置和访问记录跨 `await` 及快照恢复；枚举本身不走 `Symbol.iterator` 或 `IteratorClose`，左侧的数组解构仍走同步迭代协议。
- `Object.create(proto, descriptors?)` 用对象或 `null` 作为原型，复用 `Object.defineProperties` 的描述符转换。`Object` / `Reflect` 的 `getPrototypeOf` / `setPrototypeOf` 查询或修改内部原型，不调用 getter。成环、改变不可扩展对象的原型，或把 `Object.prototype` 的原型改为非 `null` 时，`Object` 抛出可捕获的 `TypeError`，`Reflect` 返回 `false`；把原型设为其当前值仍成功。`Reflect` 要求对象目标；`Object.getPrototypeOf` 返回字符串、数值、布尔值和 Symbol 各自的共享原型，`Object.setPrototypeOf` 验证新原型后原样返回 `null` / `undefined` 之外的原始值。宿主原生句柄的原型固定为 `null`。
- 普通对象和数组的 `Reflect.ownKeys(obj)` 按数组索引升序、其余字符串键创建顺序、Symbol 键创建顺序返回全部自有键；代理保留 `ownKeys` trap 的顺序。`Object.keys(value)` 只保留可枚举的自有字符串键，字符串原始值按 UTF-16 索引枚举。两者不遍历目标的原型链，也不为枚举而读取目标属性值。
- `Object.getOwnPropertyNames` / `Object.getOwnPropertySymbols` 按 `[[OwnPropertyKeys]]` 顺序返回自有字符串键或 Symbol 键，包含不可枚举键；代理只执行一次 `ownKeys` trap 后再过滤。字符串原始值给出 UTF-16 索引与 `length`，其它原始值返回空数组，`null` / `undefined` 抛 `TypeError`。
- `Object.values` / `entries` 一次记录全部自有键，按键表顺序跳过 Symbol，逐键重查可枚举性后立即读取值。较早的 getter 可以影响后续已有键是否输出，但新增的键不进入本次枚举。`values` 返回值数组，`entries` 返回 `[字符串键, 值]` 对的数组；稀疏数组的空洞被跳过。字符串原始值按 UTF-16 码元输出，其他非空原始值返回空数组；`null` 和 `undefined` 抛 `TypeError`。
- `Object.fromEntries` 消费同步可迭代值。每个条目必须是对象，依次读取 `0`、`1` 后转换键，再写入普通结果对象的可写、可枚举、可配置自有数据属性，不调用继承的 setter。Symbol 键保留身份，重复键覆盖而不重排，`"__proto__"` 不改变结果原型。处理条目抛出异常时关闭迭代器并保留原异常；获取或推进迭代器本身失败时直接传播异常。
- `Object.groupBy(items, callback)` 先检查 `items` 非空值、`callback` 可调用，再按同步迭代协议逐项调用 `callback(value, index)`。返回键按 `ToPropertyKey` 转换，分组按首次出现顺序保存；结果是原型为 `null` 的普通对象，每组是对应的普通数组，属性为可写、可枚举、可配置的数据属性。迭代器已取得后，回调抛错、键转换抛错或超过 `2^53 - 1` 项都会关闭迭代器并保留原异常；推进迭代器本身失败则不关闭。
- `Object.hasOwn(value, key)` 先做 `ToObject` 再转换键，因此 `null` / `undefined` 在键转换前就抛 `TypeError`。它通过 `[[GetOwnProperty]]` 查询，代理执行 `getOwnPropertyDescriptor` trap，字符串原始值暴露 UTF-16 索引与 `length`，非空原始值不创建持久包装。
- `Object.assign(target, ...sources)` 依次复制可枚举自有字符串键与 Symbol 键；每个键复制时重查描述符并读取来源属性，因此来源 getter、目标 setter 和异常均按属性操作执行。原始值目标会创建并返回包装对象，目标 setter 也以它为 `this`；`null` 和 `undefined` 作为目标会抛 `TypeError`。字符串来源按 UTF-16 索引复制，其余原始值来源及 `null` / `undefined` 跳过。`Object.is` 使用 SameValue，区分正负零并认为 NaN 与自身相同。
- `Object.defineProperty(obj, key, descriptor)` 定义或重定义自有数据或访问器属性，遵守不可扩展、不可配置和只读限制；`Reflect.defineProperty` 对定义被拒绝返回 `false`，参数转换异常仍会抛出。`Object.defineProperties(obj, descriptors)` 按自有键顺序转换描述符映射中可枚举的字符串键和 Symbol 键，全部转换成功后才开始定义；若定义中途失败，已定义的属性不会回滚。`Object.getOwnPropertyDescriptor` 查询属性而不调用其 getter。描述符可跨快照恢复。数组索引支持描述符和稀疏存储；`length` 不可枚举，缩短时不会删除不可配置的元素。
- `Object.getOwnPropertyDescriptors(value)` 按自有键顺序返回字符串键与 Symbol 键对应的完整数据/访问器描述符，不执行属性 getter；每个描述符和结果表都是独立普通对象。单数和复数两个 `Object` 入口均接受非空值原始类型：字符串有不可写、不可配置的自有索引和 `length`，仅索引可枚举。`Reflect.getOwnPropertyDescriptor` 仍然要求对象目标。
- `delete` 支持成员、计算键和可选链；只移除可配置的自有属性，不调用被删除属性的 getter，也不修改原型。不可配置键在严格模式下抛 `TypeError`，`Reflect.deleteProperty` 则返回 `false`。删除数组索引留下空洞，不改变 `length`；删除后重新添加的非索引键排在同类键末尾。删除结果和属性顺序可跨快照恢复。
- `++` / `--` 支持绑定与成员目标，包括括号括起的目标（如 `(x)++`、`++(obj.x)`、`((obj.x))--`）：目标求值一次，读旧值转为数值（Number 或 BigInt）后按同一类型加减 1 写回；前缀返回新值，后缀返回旧值。非左值目标在解析期被拒绝。
- `Object.preventExtensions` / `isExtensible`、`seal` / `isSealed`、`freeze` / `isFrozen` 控制及查询对象的扩展性和自有描述符。密封使自有属性不可配置；冻结还使自有数据属性（含数组 `length`）不可写，但保留访问器的 getter/setter，不递归处理属性值。不可扩展对象不能新增字符串键、Symbol 键或数组索引，但仍可调用继承的 setter；可写的数组 `length` 可以增长而不创建索引。`Reflect.preventExtensions` 返回布尔值，与 `Reflect.isExtensible` 一样要求对象参数。宿主原生句柄始终不可扩展。扩展性和描述符限制均跨快照恢复。
- `Object.prototype.isPrototypeOf` 从对象实参的直接原型开始按身份检查；非对象实参直接返回 `false`，对象实参与空接收者组合抛 `TypeError`。`hasOwnProperty` 和 `propertyIsEnumerable` 先转换键，再检查接收者的自有描述符，不读取属性值；对字符串原始值，有效的 UTF-16 索引是可枚举自有属性，`length` 是不可枚举自有属性，不创建包装对象。`toLocaleString` 动态读取接收者的 `toString`，以原接收者和零实参调用并原样返回结果；不可调用时抛 `TypeError`，不转发区域设置参数。不安装 `Object.prototype.__proto__` 访问器。
- 普通对象和数组都继承 `Object.prototype.hasOwnProperty`（含 Symbol 键）；数组通过共享原型提供同一个 `values` 与 `[Symbol.iterator]` 方法，游标读取实时元素并可跨 `await` 和快照续用。数组字面量展开和实参展开复用该迭代协议，已求值的元素或实参可跨 `await` 保存。Symbol 键保真身份、不参与 `length`，字符串键与 Symbol 键分别成表存储。
- `new Proxy(target, handler)` 要求对象 handler；目标可以是普通对象、数组、原始值包装对象、Date、ArrayBuffer、TypedArray、DataView，或最终转发到这些对象的代理。每次操作都从 handler 读取相应 trap；缺失、`undefined` 或 `null` 时转发到目标，其他不可调用值抛出 `TypeError`。trap 的 `this` 是 handler；`get(target, key, receiver)` 和 `set(target, key, value, receiver)` 保留原始接收者，`has(target, key)`、`deleteProperty(target, key)`、`getOwnPropertyDescriptor(target, key)` 接收转换后的字符串或 Symbol 键，`ownKeys(target)` 只接收目标。trap 查询或执行抛出的异常照常传播。
- `set`、`has`、`deleteProperty` 的结果按布尔值解释；写入或删除被拒绝时，严格语法抛 `TypeError`，对应的 `Reflect` 操作返回 `false`。违反不变量则两种入口都会抛 `TypeError`：固定的只读值、缺失访问器、不可配置属性及不可扩展目标不能被 trap 虚报。`ownKeys` 接受类数组对象，其元素必须为不重复的字符串或 Symbol；必须包括不可配置键，不可扩展时必须与实际键集一致。描述符 trap 的结果须为对象或 `undefined`，且与目标描述符及扩展性相容。数组索引和 `length` 同样参与校验。
- 成员读写、`in`、`delete` 和对应的 `Reflect` 方法使用这些 trap。`Object.keys` / `values` / `entries`、`Object.getOwnPropertyDescriptors`、`hasOwnProperty`、`propertyIsEnumerable`、对象展开/rest、`Object.assign`、`JSON.stringify` 和 `for…in` 也通过相应的属性操作访问代理。`for…in` 到达某一原型层时才记录这一层的键（代理层调用 `ownKeys`），处理尚未访问的字符串键时重新取描述符；恢复不会重新获取已到达层的键表。
- `Array` 可调用或构造；数值长度创建稀疏数组，无效长度抛 `RangeError`。`isArray` 也识别数组代理。`of` 和 `from` 可借给自定义构造器；`from` 优先使用同步迭代器，消费失败时关闭迭代器，否则在无迭代器时按类数组索引读取。
- `Array.fromAsync` 按异步迭代、同步迭代和类数组的优先级读取输入，可借给自定义构造器。它按协议等待迭代结果、同步迭代适配器或类数组的值及可选的映射结果；中止时按来源协议关闭迭代器。等待中的收集和关闭通过 Promise 反应跨快照接续。
- 数组原型方法可借给类数组或非空值原始类型。支持 `push` / `pop` / `shift` / `unshift` / `splice` / `slice` / `fill`、`map` / `filter` / `reduce` / `reduceRight` / `forEach` / `some` / `every`、`flat` / `flatMap` / `concat`、`at` / `indexOf` / `lastIndexOf` / `includes` / `find` / `findIndex` / `findLast` / `findLastIndex`，以及 `reverse` / `copyWithin` / 稳定 `sort`。`map` 和切片保留空洞，`flat` 跳过空洞。适用方法使用 `Symbol.species`，`concat` 支持 `Symbol.isConcatSpreadable`；`toSorted` / `toReversed` / `with` / `toSpliced` 不读取 species，并将空洞读作 `undefined`。
- `keys` / `values` / `entries` 每次推进时读取实时长度，耗尽后不会被追加项重新激活；`values` 与 `[Symbol.iterator]` 是同一函数。
- 同步迭代器共享 [ES2026 §27.1.3](https://262.ecma-international.org/17.0/#sec-iterator-objects) 的 `Iterator.prototype`，提供 `map`、`filter`、`take`、`drop`、`flatMap`、`reduce`、`toArray`、`forEach`、`some`、`every`、`find` 和 `[Symbol.iterator]`；`constructor` 和 `[Symbol.toStringTag]` 是访问器。`Iterator` 支持子类构造，直接调用和以自身为 `new.target` 的构造会抛 `TypeError`。
- `Iterator.from` 接受对象或原始字符串；已经继承 `Iterator.prototype` 的迭代器保持身份，否则返回缓存 `next`、按需查找 `return` 的包装对象。`Iterator.concat` 立即查找各输入的迭代方法，消费时才依序调用；提前关闭只关闭当前已打开的迭代器。包装对象及惰性 helper 均可跨快照恢复。
- `Map` 和 `Set` 必须用 `new` 构造，接受可选的同步可迭代对象。键和集合元素按 SameValueZero 比较。原型提供 `size` 访问器、增删查、`clear`、`forEach` 以及 `keys` / `values` / `entries` / `[Symbol.iterator]`。`Map.prototype` 另有 `getOrInsert` / `getOrInsertComputed`：直接查内部槽，缺失时写入实参或调用一次回调；回调的 `this` 为 `undefined` 且只接收负零归一后的键，回调抛错不回滚其自身写入。`Map.groupBy` 按回调返回值分组，同键按 SameValueZero 合并且不经过 `ToPropertyKey`；回调抛错或键数达到上限时关闭输入迭代器并保留原异常。`Set.prototype` 的 `union` / `intersection` / `difference` / `symmetricDifference` / `isSubsetOf` / `isSupersetOf` / `isDisjointFrom` 接受任意 set-like 对象：依次读取 `size`（`ToNumber`，NaN 抛 `TypeError`、负值抛 `RangeError`）、`has` 和 `keys`；按大小选择遍历自身实时集合或对方 `keys`，`difference` 遍历自身进入时的副本，提前退出对方迭代器时执行 `IteratorClose`。结果用内建原型和内部槽构造，不经过构造器、`add` 或 `species`。`Map.prototype` / `Set.prototype` 及其迭代器原型分别提供只读、不可枚举、可配置的 `[Symbol.toStringTag]`（`Map` / `Set` / `Map Iterator` / `Set Iterator`），`Object.prototype.toString` 对集合实例和迭代器返回对应标签；实例上的非字符串自有标签回退到 `Map` / `Set` 内部标签。迭代和 `forEach` 都按插入顺序读取实时数据：跳过已删除的槽位，访问尚未读到的更新和追加项，删除后重新插入会排到末尾；已结束的迭代器不会被追加项重新激活。当前实现线性查找，并保留空槽以维持游标位置，不压缩删除留下的槽。
- `WeakMap` 和 `WeakSet` 必须用 `new` 构造，分别接受可选的键值对或成员同步可迭代对象。`WeakMap` 提供 `get` / `set` / `has` / `delete`，`WeakSet` 提供 `add` / `has` / `delete`。二者按身份接受对象和非注册 Symbol（包括 well-known Symbol）；无效键在写入时抛出 `TypeError`，读取返回 `undefined`，检查或删除返回 `false`。不提供 `size`、`clear` 或迭代。
- `WeakMap.prototype.getOrInsert` / `getOrInsertComputed` 使用同一弱键规则；已存在的 `undefined` 也算命中。缺失时 computed 以原键调用回调，成功返回后覆盖回调对同一键的写入，回调抛错则保留其副作用。
- `Object(value)` 和 `new Object(value)` 为字符串、数值、BigInt、布尔值及 Symbol 创建新的包装对象；对象实参保留原身份，空值或无实参则创建普通对象。包装对象可像普通对象一样保存自有属性和内部原型，并继承各自原型上的 `valueOf` 和 `toString`；前者提取原始值，后者返回其文本。借用 `Object.prototype.valueOf` 时则返回对象本身，或为非空值原始类型创建新的包装。`Object.prototype.toString` 对原始值及其包装返回相应的类型标签，并区分 `null` 和 `undefined`。
- `String()` 返回原始字符串；无实参返回空字符串。`new String(value)` 创建字符串包装对象。原始字符串及其包装对象的 `length` 和索引按 UTF-16 码元计算；包装对象的这些成员可用 `in` 和 `Reflect.has` 检查，不可写，严格赋值抛出可捕获的 `TypeError`。原始字符串的其余属性从共享的 `String.prototype` 查找。
- `String.prototype` 提供 `charAt` / `charCodeAt` / `codePointAt` / `at`、`indexOf` / `lastIndexOf` / `includes` / `startsWith` / `endsWith`、`slice` / `substring`、`toUpperCase` / `toLowerCase`、`trim` / `trimStart` / `trimEnd`、`split` / `concat` / `repeat` / `padStart` / `padEnd` / `replace` / `replaceAll` / `match` / `matchAll` / `search`，以及 `toString` / `valueOf`。字符串分隔符直接使用；否则先查找 `Symbol.match` / `Symbol.matchAll` / `Symbol.replace` / `Symbol.search` / `Symbol.split` 协议并调用，缺失时按规范构造 `RegExp`。`replaceAll` 对非全局 RegExp 抛出 `TypeError`。
- `String.fromCharCode` / `fromCodePoint` 从 UTF-16 码元或 Unicode 码点构造字符串；`String.raw` 可直接读取 `raw` 类数组并插入替换值。JS 字符串保留任意 UTF-16 序列，包括孤立代理码元；运行时以共享的 Latin-1 或 UTF-16 存储表示字符串，克隆共享存储，写入时复制。Latin-1 字符串的 UTF-8 导出和字面子串搜索走专用路径；重复的编译期字符串常量共享常量池条目。`[Symbol.iterator]` 通过 `String.prototype` 查找，代理对一起迭代，孤立代理码元单独迭代；迭代位置可跨 `await` 快照恢复。
- `String.prototype.isWellFormed` 检查 UTF-16 是否有孤立代理码元；`toWellFormed` 只把孤立代理替换为 U+FFFD，不改动有效代理对。
- `String.prototype.normalize` 支持 NFC、NFD、NFKC 与 NFKD，仅对有效 Unicode 序列归一化并保留孤立代理码元；不涉及区域设置。另提供 Annex B 的 `substr`、旧式 HTML 包装方法，以及和标准方法共享身份的 `trimLeft` / `trimRight`。
- 正则字面量每次求值都分配新对象，不受 `RegExp` 名称遮蔽影响。固定版本的 ECMAScript 匹配器支持反向引用、前后行断言、Unicode 属性、v 集合、局部 `ims` 与命名捕获；`exec` / `test` 按 UTF-16 码元区间匹配，u 模式按 Unicode 码点匹配。全局或 sticky 成功时 `lastIndex` 写入匹配终点，空匹配不额外推进。`d` 模式返回匹配码元区间并在 `indices.groups` 引用相同区间数组；`RegExp.escape` 使用不强制转换的字符串参数。`Symbol.match` / `Symbol.matchAll` / `Symbol.replace` / `Symbol.search` / `Symbol.split` 按规范实现，替换文本支持 `$$`、`$&`、`` $` ``、`$'`、数字与 `$<name>` 捕获，可调用替换值接收位置、全部捕获和命名组对象；`String.prototype` 的对应方法先走协议查找。快照按模式和标志重建编译器，`matchAll` 迭代器保存匹配器、输入与游标。具体状态见 [`gaps.md`](gaps.md)。
- `RegExp[Symbol.species]` 由 `[Symbol.matchAll]` 和 `[Symbol.split]` 读取，允许自定义构造器和 `exec`。直接调用 `[Symbol.matchAll]` 时，无全局标志的匹配器最多产生一次匹配；`String.prototype.matchAll` 仍拒绝非全局 RegExp。
- `Number()` 无实参返回 `0`；有实参时执行现有 `ToNumber` 转换（Symbol 抛出可捕获的 `TypeError`）。`new Number(value)` 创建数值包装对象，其身份不同于所包装的数值；共享的 `Number.prototype.constructor` 指回 `Number`。原始数值不是 `Number` 的实例。
- `Boolean(value)` 返回布尔强制转换结果，无实参返回 `false`；`new Boolean(value)` 包装该结果。Symbol 包装只能通过 `Object` 创建，`new Symbol()` 抛出可捕获的 `TypeError`。
- `BigInt` 是 VM 自有任意精度原始值：`Value` 增加 BigInt 变体，数值内容由 `Arc<BigInt>` 持有，不进入定长句柄。支持十进制、`0x` / `0o` / `0b` 和数字分隔符的 `n` 字面量；`typeof`、严格/宽松相等、关系比较、算术、位运算、移位、一元 `-` / `~` 与 `++` / `--` 均按 BigInt 语义执行。除法向零截断，`%` 取被除数符号；BigInt 与 Number 混合的算术/按位运算、`>>>`、一元 `+`、负指数和除零分别抛可捕获的 `TypeError` / `RangeError`。
- `BigInt(value)` 接受布尔、字符串、整数 Number 和 BigInt；非法字符串抛 `SyntaxError`，非整数 Number 抛 `RangeError`，`null` / `undefined` / Symbol 抛 `TypeError`。`Number(bigint)` 显式允许精度丢失；`String`、模板和属性键使用规范十进制；`0n` 为假值。内建 `BigInt` 不可 `new`，提供 `asIntN` / `asUintN`、`toString(radix)`、`toLocaleString`（无区域设置）、`valueOf` 和 `[Symbol.toStringTag]`；`Object(bigint)` 创建包装对象，`Object.prototype.toString` 返回 `[object BigInt]`。`JSON.stringify` 序列化 BigInt 抛 `TypeError`，`JSON.parse` 不产生 BigInt。
- BigInt 常量、`Value`、包装对象原始值、宿主槽及 operation 交付值在构建和快照中使用 `bigint` 专用标记的规范十进制字符串，不使用 JSON 数值。快照格式 **58** 与字节码 **44** 引入该编码；宿主可用 `JsValue::bigint`（仅规范十进制）、`JsValue::as_bigint` 和 `Inspect::bigint` 读取，`InspectKind` 增加 `BigInt`。
- `Date()`、`new Date()` 和 `Date.now()` 各读取一次当前宿主时钟；`Date.parse`、`Date.UTC` 和带参构造不读时钟。Date 支持 UTC 与宿主 IANA 本地日历、完整 getter/setter、日期字符串、`toJSON`、`Symbol.toPrimitive` 和 Annex B 日期方法。本地时间遇到重叠选择较早的 instant，遇到缺口使用跳变前的偏移；远未来按内嵌 IANA 周期规则计算。`Object.prototype.toString` 识别 Date 内部槽，但字符串 `Symbol.toStringTag` 优先。
- Date 实例的内部槽为有效 Unix 毫秒或无效标记；快照格式 **57** 保存该槽和普通对象属性，不保存宿主时钟、时区或偏移。恢复拒绝越界槽值，并用新宿主解释本地时间。字节码版本不变。
- 原始值成员读取与解构从各自的共享原型查找（例如 `Symbol.prototype.description`），getter 和方法保留原始接收者，不创建包装对象。字符串的自有 `length` 和有效 UTF-16 索引优先，越界索引继续查原型。严格赋值可调用继承的 setter 并传播异常；字符串自有成员或不能创建属性的写入仍抛出 `TypeError`。
- `Number.isFinite` / `isInteger` / `isNaN` / `isSafeInteger` 不做强制转换；`Number.parseInt` / `parseFloat` 先做字符串转换，再解析有效前缀。数值常量包括 `EPSILON`、`MAX_SAFE_INTEGER` / `MIN_SAFE_INTEGER`、`MAX_VALUE` / `MIN_VALUE`、`POSITIVE_INFINITY` / `NEGATIVE_INFINITY` 和 `NaN`。
- `Number.prototype` 提供 `valueOf`、`toString`（基数 `2..36`）、`toFixed` / `toExponential`（位数 `0..100`）、`toPrecision`（精度 `1..100`）和使用默认十进制输出的 `toLocaleString`。这些方法接受数值原始值和数值包装对象；超出范围的基数、位数或精度会触发可捕获的 `RangeError`，但 `toExponential` 和 `toPrecision` 对非有限数先返回其文本。格式兼容性限制见 [`gaps.md`](gaps.md)。
- 默认十进制转换使用 ECMAScript 最短表示，供字符串转换、模板、拼接、JSON 数值和静态或动态数字属性键共用。`toFixed`、`toExponential` 和 `toPrecision` 按 ECMAScript 对实际二进制数值进行十进制舍入；非十进制整数字符串转数值仅在转换为 binary64 时舍入一次。
- `Math` 是不可调用、不可构造的普通对象。八个标准数值常量是不可写、不可枚举、不可配置的自有属性。数值方法按从左到右的顺序使用现有 `ToNumber`；`max`、`min` 和 `hypot` 转换所有实参，其他数值方法只转换所需实参。`Math.random()` 使用 VM 自有的固定种子 PRNG，返回 `[0, 1)` 中的数值；快照保留 `Math` 根及 PRNG 状态，恢复后接续原序列。
- `Math.f16round` 直接从 binary64 舍入至 binary16。`Math.sumPrecise` 消费同步 iterable，只接受 Number；对有限输入精确累加后只舍入一次，处理相消、中间溢出、无穷、NaN 与负零。消费端异常关闭迭代器并保留原异常。
- `JSON` 是不可调用、不可构造的普通对象，提供 `parse` 与 `stringify`。非有限数字写成 `null`；顶层 `undefined`、函数和 Symbol 返回 `undefined`，对象中省略这些值，数组中写成 `null`。`stringify` 支持 `toJSON`、函数或数组 `replacer` 以及 `space`，循环抛可捕获的 `TypeError`；孤立代理码元用 `\uXXXX` 转义。`parse` 只接受 JSON 语法，`__proto__` 是普通自有属性，字符串保留转义的孤立代理码元。可选 `reviver` 自底向上调用，返回 `undefined` 时删除属性。
- `JSON.parse` 为 reviver 提供第三个参数 `context`；值仍与解析所得原始值相同时，`context.source` 保留其精确 UTF-16 源文本。`JSON.rawJSON` 验证无外围空白的 JSON 原始值文本并返回冻结的无原型对象；`JSON.isRawJSON` 检查不可伪造的内部标记。`JSON.stringify` 在 `toJSON` / replacer 之后原样写入标记对象的文本，也允许用 `toJSON` 或 replacer 转换 BigInt。
- `for…of`、数组展开、实参展开和 Promise 组合子共用同步迭代协议：只读取一次 `next`，`done` 为真时不读 `value`。获取迭代器或推进迭代时的异常不触发 `return`；`for…of` 在循环体或赋值异常以及离开循环的跳转上执行 `IteratorClose`，继续同一循环和自然耗尽时不关闭。
- 数组解构复用同步迭代协议：省略项只推进，不读取 `value`；rest 收集至耗尽。正常提前结束或模式求值抛错时关闭尚未耗尽的迭代器；若模式已抛错，保留原异常。默认值或目标中的 `await` 可快照恢复，继续使用同一迭代器、已缓存的 `next` 与耗尽状态。
- `try/catch/finally`：异常表、catch 绑定、finally 正常/throw/return 完成状态、嵌套 finally、await 中的待完成状态。
- VM 自有对象表和对象 ID；对象环、Promise 反应、续体与等待关系都按 ID 保存。
- `Promise.resolve(p)` 与 `await p` 先读取真正 Promise 的 `constructor`；前者在构造器与静态方法接收者相同时复用 `p`，后者始终与内建 `Promise` 比较。复用时不读取 `then`。`resolve` 和 `reject` 需要创建结果时使用接收构造器提供的决议函数或拒绝函数。`constructor` getter 抛错会在调用点或 `await` 处同步进入脚本异常路径；成功准备的 `await` 始终经微任务恢复。
- `Promise.withResolvers()` 使用接收构造器创建 `{ promise, resolve, reject }`；`Promise.try(fn, ...args)` 同步调用回调，并用同一套决议能力处理结果或异常。原生决议函数可以跨快照保留。
- Promise 决议（包括执行器的 `resolve` 和 async 返回值）不检查输入的 `constructor`，而是同步读取一次 `then`，包括真正 Promise 上覆写的 `then`；在微任务中以输入对象为接收者调用。`then` getter 或调用抛错进入拒绝路径，非可调用的 `then` 保留输入身份，直接自决议拒绝为 `TypeError`。
- 内建包括 `Error`、`TypeError`、`RangeError`、`ReferenceError`、`SyntaxError`、`EvalError`、`URIError`、`AggregateError`、`queueMicrotask`、`BigInt`、`Promise`（构造、`resolve` / `reject` / `all` / `race` / `any` / `allSettled`，以及共享的 `Promise.prototype.then` / `catch` / `finally`）、`Symbol`（`Symbol()`、`Symbol.for` / `keyFor`，以及 `Symbol.iterator` / `Symbol.toPrimitive` / `Symbol.species`），以及原始数值全局 `NaN` 与 `Infinity`（作为运行期 `Value::Number` 提供，支持一元负号得到 `-Infinity`；不是编译期常量，也不进入快照根）。内建单例和共享原型进入快照根。`Promise` 反应、thenable 的 `resolve`/`reject` 能力和组合器状态可快照；快照时微任务队列必须为空，未根可达的 thenable 能力会拒绝快照。
- 全局 `parseInt` / `parseFloat` 与 `Number` 上的同名属性初始指向同一函数对象；全局 `isNaN` / `isFinite` 先做 `ToNumber`，不同于 `Number` 上不做强制转换的同名方法。
- `encodeURI` / `decodeURI` 和 `encodeURIComponent` / `decodeURIComponent` 先做 `ToString`，再按 UTF-8 编解码。`decodeURI` 保留 URI 保留字符的百分号转义及原始大小写；畸形转义、无效的百分号编码 UTF-8 或编码输入中的孤立代理码元抛 `URIError`。
- 全局 `eval` 不可构造，并对所有调用抛 `EvalError`（不转换参数、不解析或执行输入）。动态 `import()` 仍在编译期拒绝，`Function` 仍不能动态编译源码。
- `Symbol.for` / `Symbol.keyFor` 不读取 `this`，提取为普通函数后裸调用仍可用；`Symbol` 原型方法仍要求 Symbol 或 Symbol 包装对象接收者。
- `Symbol.prototype[Symbol.toPrimitive]` 忽略提示参数并返回接收者的 Symbol 原始值；`Symbol.prototype[Symbol.toStringTag]` 的值为 `"Symbol"`。`Symbol.unscopables` 是固定静态属性，宿主成员可使用 `WellKnownSymbol::Unscopables`；`Array.prototype[Symbol.unscopables]` 暴露 ES2026 定义的空原型名单。
- `Symbol.hasInstance` 是固定静态属性，宿主成员声明可使用 `WellKnownSymbol::HasInstance` 对应同一身份。
- `Symbol.dispose` 与 `Symbol.asyncDispose` 是固定静态属性，也可用 `WellKnownSymbol::{Dispose, AsyncDispose}` 声明宿主成员；异步宿主释放通过 `CallCx::promise` 挂起和恢复。同步迭代器和生成器从共同父级继承释放方法；异步生成器从异步迭代器父级继承对应方法。两者动态调用 `return`，异步方法同化结果并兑现 `undefined`。
- `catch` 可借用，通过普通属性读取调用原接收者的 `then`，不读取 `constructor`。`finally` 可借给对象，先选择 species，再调用接收者的 `then`；清理返回的 thenable 成功后传递原兑现值或重新抛出原拒绝原因。`then` 只接受原生 Promise，按 `constructor[Symbol.species]` 选择结果构造器并使用它提供的决议和拒绝函数。
- Promise 组合子先用接收构造器创建结果，再读取其 `resolve` 一次，接着获取同步迭代器。逐项以构造器为接收者调用 `resolve`，立即调用返回值的 `then`，不增加微任务。组合子直接使用构造器提供的能力函数；逐项计数只记第一次调用，按输入求值顺序生成数组或 `AggregateError.errors`。迭代期间的脚本错误调用构造器提供的拒绝函数。快照格式 **52** 保存可达的逐项回调及其共享状态。
- 标准 Error 构造器均可直接调用或用 `new` 构造，提供继承的 `name`、可选自有 `message` 和自有 `stack` 数据属性。`stack` 首行保留名称和消息；创建时按由内向外的顺序附加最多 10 个可见同步脚本帧，格式为 `    at <name> (<module>:<line>:<column>)`。行、列从 1 开始，列按 UTF-16 码元计算。抛出、重抛、拒绝和快照恢复都不重新捕获。各子类原型继承 `Error.prototype`，共享同一个 `toString`：可写、不可枚举、可配置。它动态读取接收者的 `name` 与 `message`（缺失时分别为 `"Error"` 和空串），先转换 `name` 再转换 `message`，消息为空串时返回 `name`，否则返回 `name: message`；`null` / `undefined` 接收者抛 `TypeError`，非字符串值按字符串 hint 转换，读取或转换中的异常原样保留。`AggregateError` 同步遍历第一个参数并创建自有数组 `.errors`。VM 生成的 `TypeError` 和 `RangeError` 使用相应内建原型。
- Error 和原生错误构造器（包括 AggregateError）可从 `options` 读取继承或自有的 `cause`，作为不可枚举的自有属性安装；缺少该属性时不安装。原生错误构造器继承 `Error`，其原型各自拥有空的 `message` 数据属性。
- `Error.isError(value)` 识别实际的 Error 内部标记（包括子类和 VM 自身创建的 Error），不依赖原型、`instanceof`、`Symbol.toStringTag` 或属性读取。
- `DOMException` 必须用 `new` 构造；原型继承 `Error.prototype`。`name`、`message` 和旧式 `code` 由带品牌检查的只读 getter 提供，构造器和原型均定义历史常量。快照格式 **68** 保存内部名称和消息以及新增的内建根；字节码与二进制容器版本不变。
- `Event`、`CustomEvent` 和 `EventTarget` 使用 VM 内部品牌，保留普通属性和子类原型；`globalThis` 本身是事件目标。`CustomEvent.detail` 按引用保存，事件时间戳以 VM 单调时钟为基准，恢复不累计离线时间。`structuredClone` 不克隆这些平台对象。
- `EventTarget` 按捕获与非捕获两遍同步调用目标监听器；支持 `once`、`passive` 和动态 `handleEvent`。监听器脚本异常进入 VM 的全局错误报告，不中断后续监听器，也不在监听器之间排空微任务。快照格式 **69** 保存目标、监听器、事件内部状态和 VM 相对时钟；恢复不重新登记监听器。
- 标记的 Rust 宿主实例直接参与事件传播，不分配代理目标。每次派发先固定父槽路径，再依次捕获、调用目标监听器和冒泡；回调中修改父槽仅影响后续派发。CPS 宿主派发使用固定入口，不读取脚本可覆盖的 `dispatchEvent`。
- `AbortController` 与 `AbortSignal` 保留取消原因身份；`AbortSignal.any` 先标记受影响信号，再按源、依赖的登记顺序执行取消步骤和可信 `abort` 事件。`{signal}` 依据监听器登记 ID 清理，不受事件传播停止影响。快照格式 **70** 保存取消图及 pending operation 关联。
- `setTimeout` / `setInterval` 共用正整数 ID，接受可调用对象和 Web IDL `long` 延时；`clearTimeout` / `clearInterval` 可交叉取消。回调保留参数身份，以 `globalThis` 为接收者，异常走全局报告；任务间执行微任务检查。interval 从本轮结束重新登记，不补跑。`AbortSignal.timeout` 共用可选的 `timer`（`TimerService`） 唤醒服务，异步触发带 `TimeoutError` 的可信 `abort`。
- `Performance` 不可直接调用或构造。`performance` 是有独立品牌的 EventTarget 单例，全局属性可替换；`now()` 返回 VM 相对单调毫秒（含小数），`timeOrigin` 恒为 `0`，`toJSON()` 每次返回新的 `{timeOrigin: 0}`。不需要宿主服务，也不读取 Date 墙钟。
- 快照格式 **73** 以秒、纳秒保存 VM 相对时钟和截止时间，保留定时器记录、分配游标及普通任务队列，不保存平台登记。恢复重新锚定且不计离线时间；到期任务依截止时间和调度序号入队，未到期者按向上取整的剩余毫秒登记。字节码与容器编码不变。
- 同步全局 `structuredClone(value, { transfer })` 在同一 VM 内创建新对象图，保留循环与共享引用。普通对象复制可枚举自有字符串键，数组保留洞；Map、Set、日期、正则、错误、包装原始值和二进制视图按内部类型重建。转移列表转参和校验先于遍历，遍历成功后按顺序移动 `ArrayBuffer` 后备存储；后项失败不回滚前项。不可克隆值抛出 `DataCloneError`，用户 getter 或转参抛出的值原样传播。快照格式 **68** 同时登记该函数的固有根。
- `SuppressedError(error, suppressed, message?)` 不读取 `cause` 选项，前两个值存为可写、可配置、不可枚举的自有属性。快照格式 **62** 保存新增的固有根并保留两个释放协议 Symbol。
- `DisposableStack` / `AsyncDisposableStack` 在登记时捕获方法，按 LIFO 释放；`move` 只转移记录。释放先标为 disposed，重入不重复调用。异步栈每次释放返回新的原生 Promise，区分真正异步方法、同步回退和空记录的等待边界。快照格式 **63** 保存可达记录、异常与待继续的释放反应；恢复从尚未调用的记录继续，不重新执行已经弹出的记录，GC 不代为释放。
- 快照格式 **64** 增加编译器私有清理函数根；这些函数不出现在全局名表或 `globalThis`。字节码仍使用现有的 `GetBuiltin`、调用和 `Await` 指令。
- 快照格式 **65** 保存 raw JSON 内部标记、`Array.fromAsync` 的等待状态、迭代器 helper 游标、代理撤销状态及 `Symbol.unscopables` 固定身份；不迁移旧格式，字节码版本不变。
- 快照格式 **66** 增加 URI、数值与 `eval` 全局函数的内建根；字节码版本不变。
- 快照格式 **67** 增加 `Iterator` 与包装迭代器原型的内建根，保存包装记录和 `Iterator.concat` 的游标；字节码版本不变。
- 错误消息、`Symbol()` 的描述和 `Symbol.for()` 的键使用字符串 hint 转换。借用 `Array.prototype.join` 或 `toString` 时，接收者可以是对象或非空值原始类型。`join` 先按数字 hint 转换 `length`、截断并限制在 `0..=2^53−1`，再转换分隔符；原始字符串直接按 UTF-16 码元连接，不创建包装。若继承的 getter 或代理可观察接收者，则使用同一个包装对象；`toString` 也以该包装调用查找到的 `join`。数组 `length` 的赋值和定义依次执行 `ToUint32` 与独立的 `ToNumber`；结果不一致抛出 `RangeError`。这些入口都保留转换方法抛出的原值。
- `CallCx::promise(op)` 创建一个原生 VM Promise 作为交付目标；后台任务使用相同的 operation 登记路径，并将稳定、可取消的正安全整数句柄返回给 JS。VM 先创建 operation 记录，再调用已链接的 `OperationDriver::start`。登记对象的 `Drop` 释放平台资源；`checkpoint` 只更新镜像状态。捕获时宿主必须保持外部逻辑时间和投递在同一切点。旧代、重复及未知令牌被拒绝。`Pause` 和 `Reject` 在恢复时结算原目标；`Resume` / `Reissue` 由 `Vm::start_recovered_operations()` 在发布后重新登记，失败只拒绝该目标。
- 宿主导出函数、原型方法和访问器都是 VM 自有函数对象；调用目标按声明 ID 分派，普通属性及内部原型随快照保存。函数对象支持 `bind`、`call` 和 `apply`。
- `host!` 在编译期拒绝选中消费者缺少必需的自定义服务，以及同一确切类型（含别名）的重复注册。每个宿主构造独立的消费者视图，回调直接借用视图字段；宿主侧的 `bind_service::<T>()` 仍可按类型查询。视图、布局和实例不进入快照或绑定指纹。
- `CallCx::type_error(message)` 创建可由脚本捕获的 `TypeError`：`message` 原样保留，`stack` 首行只加一次 `TypeError: `，随后记录可见的同步脚本调用帧。
- `JsError::type_error(message)` 以惰性形式构造同一类错误：立即只保存消息，进入脚本时才由 VM 分配 `TypeError` 对象，宿主可在持有服务借用等不便调用 `CallCx` 的位置使用。
- `CallCx::instance<T>` 通过 VM 品牌检查已有宿主实例，接受派生类以访问继承槽，不改变实际 payload 类型。`Instance::init_object_field` 在新实例上定义独立的普通对象数据字段，不调用 setter，也不覆盖已有自有属性。
- 引擎内建函数与宿主函数共用 native 调用入口，但不经过宿主 ABI。快照以 `(owner, slot, member)` 重链接内建 handler，并保留函数的自有属性、原型和身份。未知键或同一声明对应多个函数对象时拒绝恢复；多个属性仍可共享同一函数对象。
- `reportError(value)` 同步向 `globalThis` 派发可信、可取消的 `ErrorEvent`；监听器、后台宿主任务及 `queueMicrotask` 的未捕获异常走同一入口。消息和位置不经脚本 getter 或转换；仅未取消的报告交给可选的 `diagnostics`（`Diagnostics`），事件为 `Diagnostic::Uncaught`。错误报告期间再次抛出的异常直接报告，不递归派发。单独的 `Diagnostic::StartupException` 在模块初始化异常返回前报告，不派发脚本事件或更改返回错误。没有服务时只省略宿主报告。
- 微任务成功排空后，VM 将仍未观察的拒绝移入普通 FIFO 任务，批次中不穿插微任务。每项派发前重新检查，仍未观察的项收到可信且可取消的 `unhandledrejection`；仅未取消的事件产生 `Diagnostic::UnhandledRejection` 报告。报告后首次观察会排入独立的非可取消 `rejectionhandled` 任务，不调用诊断服务。`.then()` 即使未提供拒绝回调也算观察，透传给子 Promise 的拒绝独立判定。
- `ErrorEvent` 与 `PromiseRejectionEvent` 可由脚本构造为不可信事件，字段以只读原型访问器读取内部状态。全局的 `onerror`、`onunhandledrejection`、`onrejectionhandled` 与普通监听器共用登记顺序；非空替换保留位置。`onerror` 接收全局 `error` 事件的五个 `ErrorEvent` 字段，严格返回 `true` 时取消；其他处理器接收事件，严格返回 `false` 时取消。快照格式 **72** 保存事件内部值、处理器登记、拒绝候选及任务；恢复不派发。字节码 **56** 添加三个固定内建操作数，其他三个处理器名访问可变全局属性；二进制容器不变。
- 快照与运行期 GC 共享只读追踪：从 operation 的 Promise 终点、待交付的拒绝通知、宿主任务的接收者和保存槽、内建单例、类原型、模块状态槽、顶层环境及宿主显式根出发，沿堆边访问可达的 async 续体和闭包环境。排队宿主续体的交付值由微任务追踪。well-known Symbol 和注册表项恒为根；普通 Symbol 由可达引用（包括属性键）或宿主显式根保留。
- 宿主可在 VM 调用之间、排空微任务后显式调用 `Vm::collect_garbage(&[roots])`。它原地回收不可达对象（包括环）及其旁表、宿主实例和续体，清除不可达普通 Symbol，只返回删除的堆对象数；不改变存活 ID，也不复用被回收的 ID。宿主每次须显式提供仍要使用但不由 VM 持有的本 VM `Value`；这不延长临时宿主绑定 `JsValue` 的有效期。GC 不执行微任务、脚本或宿主绑定回调，标记失败不清扫。与快照不同，GC 可丢弃不可达且未调用的决议能力。
- 宿主绑定可选择通过 `CallCx::request_gc` 暴露同步 GC。VM 在当前 `CallCx` 结束后追踪活动帧、跨调用的 Rust 值、排队及正在派发的微任务，以及可选的 `gc_roots`（`GcRoots`） 服务借出的本 VM 值。宿主可直接访问持有值的字段，允许重复报告，不得在访问期间重入 VM；显式收集和快照仍各自接收根切片，不读取该服务。活动收集成功后以删除的对象数恢复宿主绑定，不排空或重排微任务，也不改变快照边界；追踪失败直接返回 VM 错误，不清扫或恢复宿主绑定。
- 宿主绑定宏将 `call`、`gc` 和后台块内的 `effect` 降为状态机的挂起边。支持结构化 `if` / `match`、`loop`、`while` 和 `while let`，以及带标签的 `break` / `continue`；每个语法上的 `await` 固定占用一个恢复阶段，循环再次到达时复用该阶段。`await?` 将拒绝或 guest throw 沿当前宿主异常路径传播。只保存在等待边上存活的 guest 值，方法的 `This<T>` 从原接收者重建。绑定指纹包含持久阶段的类别、活槽布局和接收者类标签，不包含 Rust 函数指针或内部状态机节点号。
- 恢复同时验证外部 operation 与宿主任务的双向关联、pending Promise 目标、任务高水位、owner / 恢复阶段、活槽值及方法接收者。只有外部等待阶段可以写入格式 49 的镜像。任一校验失败整体拒绝，不登记平台工作、不执行脚本。
- `ArrayBuffer`、`DataView` 与 `%TypedArray%` 加 12 个具体构造器都是 VM 内建对象。缓冲区持有唯一的字节块和可选 `maxByteLength`；视图只记录 `buffer` / `byteOffset` / 可选 `byteLength`，从不由视图复制字节。`ArrayBuffer` 提供 `byteLength` / `maxByteLength` / `resizable` / `detached` 访问器、`ArrayBuffer.isView`、按 species 构造的 `slice`，以及 `resize`、`transfer`、`transferToFixedLength`：传输先读取策略，`preserve-resizability` 保留可调整性，`transferToFixedLength` 总是得到固定长度缓冲区，旧缓冲区随即分离。零长度缓冲区合法。`%TypedArray%` 本身不可调用也不可构造，因此不是全局名。
- 具体 TypedArray 构造器接受长度、`(buffer, byteOffset?, length?)`、TypedArray 或类数组/可迭代来源；长度按 `ToIndex` 校验，越界抛可捕获的 `RangeError`。`buffer` / `byteOffset` / `byteLength` / `length` 是 `%TypedArray%.prototype` 上的共享访问器，具体原型只额外拥有 `BYTES_PER_ELEMENT` 与 `[Symbol.toStringTag]`，`values` 与 `[Symbol.iterator]` 是同一个函数对象。没有显式长度的视图在可调整缓冲区上按实时长度伸缩，其余视图保持固定；调整后越界的视图长度为 0，元素读写静默丢弃而 `DataView` 抛 `RangeError`，缓冲区重新增长时视图之外的字节为 0。分离缓冲区上的任何视图访问都抛可捕获的 `TypeError`。
- 元素编码分 Number 与 BigInt 两个域：整数按宽度取模回绕，`Uint8ClampedArray` 做 round-half-to-even 钳制，`Float16` 从 binary64 直接舍入一次；BigInt 视图拒绝 Number 输入，Number 视图拒绝 BigInt。`DataView` 提供全部 11 种宽度的 `get*` / `set*`，默认大端，`getFloat16` / `setFloat16` 与 `BigInt64` / `BigUint64` 成对存在。
- 视图的整数索引按 CanonicalNumericIndexString 判定：`""`、`"-0"`、小数和前导零等非规范形式按普通属性处理（因此会走原型链），其余规范索引越过长度即无效——读取给 `undefined`、写入静默丢弃、不创建属性、`deleteProperty` 返回 `false`，也不调用继承的 setter。`ownKeys` 先给升序索引再给其余自有键；`Object.freeze` 对含元素的视图抛 `TypeError`，空视图可以冻结；自动长度视图的 `preventExtensions` 抛 `TypeError`。属性读取、写入、`in`、删除、属性描述符和代理转发共用这一判定。
- `%TypedArray%.prototype` 提供 `at`、`copyWithin`、`every`、`fill`、`filter`、`find` / `findIndex` / `findLast` / `findLastIndex`、`forEach`、`includes`、`indexOf`、`lastIndexOf`、`join`、`map`、`reduce` / `reduceRight`、`reverse`、`set`、`slice`、`some`、`sort`、`subarray`、`toLocaleString`、`toReversed`、`toSorted`、`with`、`values` / `keys` / `entries`，`toString` 就是 `Array.prototype.toString`。`slice` / `map` / `filter` 使用 species，`with` / `toSorted` / `toReversed` 使用内建构造器；无比较器的 `sort` 做数值排序（NaN 最后、`-0` 在 `+0` 之前），`set` 在来源与目标共用一个缓冲区时先取快照。`from` / `of` 是 `%TypedArray%` 的静态方法，`from` 用接收构造器创建结果并支持映射函数与 `thisArg`。
- `Uint8Array` 另外提供 `fromBase64` / `fromHex`、`toBase64` / `toHex`、`setFromBase64` / `setFromHex`。解码支持标准与 `base64url` 字母表、忽略 ASCII 空白、`loose` / `strict` / `stop-before-partial` 末段策略，`setFrom*` 以目标长度为上限截断并返回 `{ read, written }`，非法输入抛 `SyntaxError`。编码支持 `omitPadding` 与 `base64url` 输出。
- 全局 `atob` / `btoa` 是不依赖宿主的 HTML 字符串 API，同时作为裸名及 `globalThis` 属性暴露。`atob` 忽略 ASCII 空白，接受合法的无填充输入，按字节返回 U+0000–U+00FF 码元；`btoa` 只接受该范围的码元，输出带填充的标准 Base64。非法输入抛 `DOMException`（`InvalidCharacterError`）。
- `self` 与 `navigator` 同时作为静态裸名与 `globalThis` 属性暴露。`self` 的初始值是 `globalThis` 对象本身；`navigator` 是 VM 自有的普通对象，只提供只读、可配置、可枚举的 `userAgent` 与 `platform` 自有数据属性。`userAgent` 从 `UserAgent` 服务读取，缺省为 `yield-js`，仅用于识别脚本运行环境，与 Fetch 实际发出的 `User-Agent` 头无关；`platform` 是二进制编译目标平台的 `<target_os>-<target_arch>`，不是宿主运行机器或浏览器平台字符串。快照格式 **88** 增加 `navigator` 内建根并保存其属性，恢复不重新读取宿主配置。
- `crypto` 始终作为静态裸名与 `globalThis` 属性暴露，原型的 `[Symbol.toStringTag]` 为 `Crypto`。`getRandomValues(view)` 只接受整数 TypedArray（含 `Uint8ClampedArray` 与两种 BigInt 视图），按原始字节填充当前视图范围并返回同一对象；参数类型不符抛 `TypeMismatchError`，分离或越界视图抛 `TypeError`，超过 65,536 字节抛 `QuotaExceededError`。`randomUUID()` 单次请求 16 字节，返回小写 RFC 4122 v4 UUID。两个方法仅使用显式安装的 `crypto`（`CryptoService`） 熵服务；缺少服务时抛 `NotSupportedError`，服务失败时抛 `OperationError`。快照格式 **89** 增加 `crypto` 单例和原型根，不保存熵服务或其状态。
- `crypto.subtle` 是只读访问器，每次返回同一 `SubtleCrypto` 实例。`SubtleCrypto` 与 `CryptoKey` 有原型、品牌检查与不可直接构造的全局接口对象。`digest` 支持 SHA-256；`importKey` / `exportKey` 支持 raw AES-GCM、HMAC-SHA-256 与 PBKDF2 密码；`deriveKey` 支持 PBKDF2-SHA-256 到 AES-GCM；`encrypt` / `decrypt` 支持 AES-GCM；`sign` / `verify` 支持 HMAC-SHA-256。AES 支持 128/192/256 位密钥；GCM 的附加数据可省略，标签默认 128 位，允许 32/64/96/104/112/120/128 位。认证失败拒绝 `OperationError`。
- SubtleCrypto 在调用时复制 BufferSource 的可见字节，单个输入最多 64 MiB；所有方法返回异步结算的原生 Promise，缺少独立的 `subtle_crypto`（`SubtleCryptoService`） 时拒绝 `NotSupportedError`，不影响随机方法。快照格式 **90** 保存可导出 `CryptoKey` 的元数据与原始字节；不会保存进行中的原语请求，存在待交付请求时捕获失败。当前协议没有可恢复的 opaque key，因此拒绝导入或派生不可导出密钥；PBKDF2 密码在此子集中也只能作为可导出 raw 密钥使用，与标准 Web Crypto 的 PBKDF2 可导出性要求不同。
- SubtleCrypto 原语由宿主调度；已就绪的请求无需等待更早提交的请求。每个 VM 最多保留 16 个待交付请求，超限的请求以 `OperationError` 拒绝。
- `TextEncoder` 与 `TextDecoder` 是 VM 内建构造器。`TextEncoder.encode` 将 `USVString` 编为 UTF-8（孤立代理码元替换为 U+FFFD），返回新的 `Uint8Array`；`encodeInto` 写入实际的 `Uint8Array`，不拆分多字节序列，结果 `{ read, written }` 分别计 UTF-16 码元与字节。`TextDecoder` 支持 UTF-8、UTF-16LE、UTF-16BE 的标准别名，去掉首尾 ASCII 空白并按 ASCII 忽略大小写；其他标签抛 `RangeError`。`decode` 接受 `ArrayBuffer`、`DataView` 或任意 TypedArray 的原始字节窗口，`stream: true` 时保留未完成序列，最终调用处理剩余字节。非 fatal 模式用 U+FFFD 替换非法序列；fatal 模式抛 `TypeError`，流仍开启时保留出错序列之后的待处理字节。每个新流只剔除首个 U+FEFF，`ignoreBOM: true` 时保留。方法及访问器检查实例品牌。
- 快照保存缓冲区字节与 `maxByteLength`（分离记为空）、视图的 `buffer` / `byteOffset` / `byteLength` / 元素种类，以及 Array 迭代器记录中的字节视图游标。快照格式 **75** 另记录 `TextDecoder` 的编码，与已有的 `fatal` / `ignoreBOM`、流标记、BOM 已见标志、未完成前缀及 fatal 流错误留下的待处理字节一起恢复。完整校验拒绝与编码或流状态不一致的记录。字节块与视图在运行期 GC 与快照追踪中都按强引用边处理。
- `CountQueuingStrategy` 与 `ByteLengthQueuingStrategy` 的 `highWaterMark` 为必需的 unrestricted double；实例访问器检查品牌，`size` 返回同一 realm 共享的函数。计数函数返回 `1`，字节长度函数按普通属性访问读取 `chunk.byteLength`。快照保留高水位数值和共享函数身份。
- `ReadableStream` 的普通读取路径包含默认 reader 与 controller、带大小的 FIFO、锁和取消。控制器 `start` / `pull` 的等待与 reader 的 `closed`、待完成读取均随快照保存；恢复不重调已开始的用户回调。
- 字节读取支持默认 reader 自动分配和 BYOB reader 的 `min`、偏移及元素边界。字节队列保存缓冲区区间；同长转移移动后备存储并分离旧缓冲区。快照保留未完成的 pull-into 和 BYOB request，完整校验检查关联、区间与对齐。
- `TransformStream`、`pipeTo` / `pipeThrough`、`tee` 与 `ReadableStream.from` / 异步迭代由 VM 内部端点组合。默认可读 HWM 为 0、可写为 1；pipe 尊重三个 prevent 标志与 `AbortSignal`，tee 分普通与字节分支，迭代器串行执行 `next` / `return`。未完成步骤、锁、取消原因和端点关联均随快照保存。
- `TextEncoderStream` 与 `TextDecoderStream` 复用编码内建与标签规则，提供固定的 `readable` / `writable` 端点；编码器跨块保留高代理并在 flush 时替换一次，解码器按 UTF-8/UTF-16 增量处理且无输出时不入队。编解码进度随快照恢复。
- `CompressionStream` 与 `DecompressionStream` 支持 `gzip`、`deflate`、`deflate-raw` 与 `brotli`。编码器跨 64 KiB 输入块产生单个合法流，gzip/zlib 包装与 CRC32/Adler32 随外层状态推进；解码器接受任意合法块、跨块回引和校验，拒绝截断、尾随数据与非法头。位缓存、窗口、熵表和包装游标随快照保存而不重放历史输入。
- `URL`、`URLSearchParams`、`URLPattern` 同时暴露为静态裸名与 `globalThis` 属性，不依赖宿主服务。`URL` 支持组件读写、`toString` / `toJSON` 与静态 `parse` / `canParse`；`URLSearchParams` 支持字符串、键值对序列和记录初始化、查询修改、排序与实时迭代；`URLPattern` 支持字符串与字典、组件访问器、`test` / `exec`。
- `VmOptions::base_url` 在模块求值前设置绝对基准 URL，只用于构造器省略 `base` 时的解析，不改变静态方法。快照格式 **74** 保存基准、URL 与查询列表的双向链接、迭代游标及模式输入；恢复只使用快照保存的基准（也保留无基准的情况），不能通过 `RestoreOptions` 覆盖，也不重新运行模块初始化。
- `Blob`、`File`、`FormData`、`Headers`、`Request`、`Response` 与 `fetch` 同时作为裸名和 `globalThis` 属性，不依赖网络即可构造和消费。Blob 复制可变 BufferSource 的有效窗口，切片共享不可变字节；File 持有 `name` 与 `lastModified`，structured clone 保留 Blob/File 品牌和内容。FormData 保留重复项和顺序；Headers 保留原始字节对、排序合并后的公开视图、guard 与 `getSetCookie()`；Body mixin 共享同一字节流状态，`bodyUsed` 由流状态派生，clone 使用 tee。`URL.createObjectURL` 在本 VM 保活对象，撤销只影响后续解析。
- `fetch` 实现 `about:blank`、`data:`、本 VM 的 `blob:` 与 HTTP(S) 单跳算法：CORS 预检、响应头过滤、重定向及跨源头清理、307/308 不可重放体拒绝、`only-if-cached` 不联网、gzip/deflate/br 单次解码、SRI（sha256/384/512）、keepalive 64 KiB 预算，以及保留脚本 reason 的 abort。上行按宿主额度从原流读取，下行只在授予额度内投递。无 `fetch`（`FetchService`） 时 HTTP Fetch 以 `TypeError` 拒绝；404/500 是正常响应。
- 快照格式 **86** 保存上述记录、迭代游标、对象 URL 表、fetch 环境（origin、referrer、分区与授权标识）和逐事务阶段。恢复先消费镜像中已接受的事件，再以 `AbortError` 中断仍依赖外部传输的事务：未暴露的响应拒绝原 Promise，已暴露的响应只让未完成的体出错，已完整接收的体继续可读。恢复不重发请求，也不启动新传输；宿主授权域不一致时拒绝恢复。
- `Number`、`BigInt` 及其共享原型是快照根；`Number.NaN` 和正负无穷常量通过专用数值编码跨 JSON 快照往返保留。
- 编译器接受溢出为无穷的数字字面量；`NaN` 和 `Infinity` 仍按作用域解析。字节码版本 **31** 的 Build 常量和快照值共用 JSON 数值编码：有限值保留数值形式和负零，非有限值用专用字符串标记，NaN 不保留 payload。宿主返回值、槽与异步操作的兑现值和拒绝原因均可包含非有限数。
- `Map`、`Set` 构造器及其共享的实例原型和迭代器原型是快照根；条目顺序、对象及 Symbol 的身份、迭代器的游标和已耗尽状态可跨快照保留。
- 快照格式 **51** 保存 Array 迭代器的种类、源对象及 64 位游标，并保留 `Symbol.isConcatSpreadable` 的固定身份；不迁移旧快照。
- `WeakMap` 和 `WeakSet` 的构造器及共享原型是追踪根。只有 WeakMap 和键都可达时才追踪对应值，反复处理直至没有新增可达对象或 Symbol。WeakMap 键和 WeakSet 成员本身都不是强引用。快照省略不可达键的条目，运行期 GC 原地删除这些条目；恢复拒绝悬空键和注册 Symbol 键。快照格式 **48** 用 `o:<ID>` 和 `s:<ID>` 区分两种弱键，不迁移旧快照。
- `Proxy` 构造器是快照根；代理到目标、handler 的边是强引用，handler 捕获的闭包环境沿普通堆边保存。保存和恢复直接处理记录，不通过 trap 查询代理。恢复拒绝缺失或类型不合法的代理引用。
- `Proxy.revocable` 使用与 `new Proxy` 相同的目标限制；撤销时清除目标、handler 和撤销函数对代理的引用，重复调用无效果。访问已撤销代理会在相应内部操作抛出 `TypeError`，包括 `Array.isArray` 穿过代理链时；撤销前后的对象身份与状态均可跨快照保留。
- 快照格式 **39** 保留 `Symbol.hasInstance` 的固定身份，并校验保留描述和注册表。快照保存包装对象的原始值、自有属性、原型和对象身份，以及共享内建根、绑定指纹、类原型映射、可达宿主实例的槽/payload 和模块状态。可达的 Symbol 包装对象保留被包装的 Symbol，即使没有其他引用；恢复拒绝悬空的 Symbol 引用。
- 字节码格式 **31** 和快照格式 **39** 保留所有 UTF-16 码元。宿主与快照共用字符串编码：合法 Unicode 序列写作 JSON 字符串，含孤立代理时写作 `{"utf16":[...]}`；JS 字符串键映射以有序键值对写入，恢复拒绝重复键。
- 快照要求微任务队列已排空。显式根只扩充捕获时的可达对象图，不作为宿主持有的根清单写入镜像；恢复后也不自动注册为 GC 根。
